# E2E テスト (Windows 専用)

`tauri-driver` + WebdriverIO で、実際にビルドしたリリース版 (`just bundle` の成果物) を操作して確認する。
配る物そのものを試すのが目的なので、テスト専用のプラグインなどは埋め込まない。

## 前提

- Windows。macOS は WKWebView に外部ドライバーがなく tauri-driver を直接使えないため対象外。
  - macOS でも、アプリに WebDriver のサーバーを埋め込む `tauri-plugin-wdio-webdriver` (webdriverio/desktop-mobile、MIT。2026-09-25 時点で v1.4.0) を使えば回せる。採らないのは次のため。
    - アプリのビルドに埋め込むので、E2E 専用のビルドが要り、配る物そのものを試せない。
    - クリックやキー入力は JS で合成したイベント (`isTrusted` が false) で、IME・グローバルホットキー・フォーカス・トレイは確かめられない。OS で違いが出るのはそこなので、macOS はアクセシビリティで見る (「macOS の確認」)。
    - Windows の機が使えなくなったときや、macOS だけで画面の中身の不具合が続くときは見直す。
- `cargo install tauri-driver`
- リポジトリ直下に `msedgedriver.exe` を用意する。WebView2 のバージョンと合わせる必要があるので、
  `cargo install --git https://github.com/chippers/msedgedriver-tool` などで入れた `msedgedriver-tool`
  を実行すると、入っている WebView2 に合わせて自動でダウンロードしてくれる。
- 常用の Mawok が起動していると single-instance でテスト用のプロセスが起動できない。
  書きかけのテキストを消さないよう、自動では終了せず `ensureMawokNotRunning()` がはっきり
  失敗する (`lib/os.mjs`)。実行前に、書きかけのテキストがあれば確定させたうえで手動で終了しておく。

## 実行

```
just e2e
just e2e draft-clipboard settings-replacements
just e2e --no-build
just e2e --no-build tray
```

`just bundle` でビルドし直してから、`e2e/tests/*.test.mjs` をファイル名順に1つずつ実行する。
引数でテストファイルを選べる。`draft-clipboard` のように名前だけなら `tests/<名前>.test.mjs`、パスやグロブならそのまま使う。選んだファイルは1つずつ `node` で直接回す (`node --test` は通さない。下の「中断したときに残るファイルは、次の実行が片付ける」)。
入口は `e2e/run.mjs` で、ビルドの前に画面がロック・スタンバイ中でないことを確かめ、ビルドとテストが終わるまで画面を点けたままにする (「注意点」の画面のロックの項を参照)。

**`--no-build` を付けると、ビルドだけを飛ばす。** 画面とスタンバイの面倒はこれまでどおり見る。ファイルの選択と一緒に使える。
使いどころは、**コードを変えずに続けて何度も回すとき** (間欠的に落ちるものを追うなど)。ビルドは1回あたり3分半ほどかかり、変えていなくても走る。`vite build` がフロントの成果物を毎回書き直すので、cargo がそれを入力の変化と見て建て直し、リンクと NSIS のインストーラー作成まで続くため。
**成果物の新しさで自動では飛ばさない。** 自動にすると、古いビルドで回していることに気づかないまま通ってしまう。飛ばすかどうかは、毎回その場で決める。
飛ばしたときは、どのビルドで回すのかを最初に出す。実行ファイルの場所とビルドした時刻、今の HEAD とそのコミットの時刻、作業ツリーに変更があるか。HEAD のコミットが実行ファイルより後のとき、作業ツリーに変更があるときは、`※` を付けて言う (実行ファイルの更新時刻との比べなので、目安であって保証ではない。古いコミットに戻した後などは、新しくなくても中身は合っていない)。
実行ファイルが無いときは、黙ってビルドせずに、その旨で落ちる。
tauri-driver は各テストファイルの `before` フックが自分で起動・終了するので、事前に手動で
立ち上げておく必要はない。

初回だけ依存のインストールが要る:

```
cd e2e
pnpm install
```

## 描かれ方と画面の撮影

`tests/rendering.test.mjs` は、画面の状態ごとに、テーマ・言語・大きさを変えながら `lib/rendering.mjs` で描かれ方の崩れ（重なり・はみ出し・省略・潰れ）を調べ、WebView の中を `e2e/screenshots/<状態>-<言語>-<テーマ>[-min].png` に撮る（gitignore 済み。実行のたびに消して撮り直す）。

- 撮った画面は人かエージェントが目で見る。気づいたものは直すか、直さない理由を残す。
- 直す前の崩れがあるテストは `todo` にしてある（落ちても全体は通り、`todo` の数に出る）。直したら外す。
- 状態を足すときは、`inspect` に状態の名前と、上に出す部品（`overlays`）・窓に収まるべき押せない部品（`inViewport`）を渡す。3 秒で消える知らせのように撮るたびに作り直す状態は `prepare` で作る。
- **AI のアクションを選ばない**。この機の資格情報管理に本物のキーがあると、テストのテキストが AI サービスへ送られる。画面の `window.__TAURI_INTERNALS__.invoke` は書き換えても効かないので、画面の側で止めることもできない。

## MSIX 版の確認

```
just msix-check
just msix-check --no-build
just msix-check msix        # msix/msix.test.mjs だけ
```

`e2e/msix/msix.test.mjs`。tauri-driver はパッケージの中の `mawok.exe` を動かせないので、MSIX 版だけの作りはここで別に見る。

- **動かし方**: `just msix` で作り直した MSIX を入れ、`Invoke-CommandInDesktopPackage` でパッケージの中から、環境変数 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` で CDP の口 (9340) を開けて起動する。画面が呼ぶのと同じコマンドを CDP で `window.__TAURI_INTERNALS__.invoke` に送り、結果を OS の側で読む (`lib/msix.mjs`)。
- **常用版との入れ替え**: 常用の MSIX 版と同じパッケージなので、動いている Mawok (MSIX 版でも EXE 版でも) を終了し、外してから入れる (同じ版番号のまま上から入れられないため)。元から MSIX 版が入っていれば、終わると**試した版が常用版として残る** (外した版の MSIX は手元に残らないため)。入っていなければ外す。ログイン時の起動 (StartupTask) の状態は元に戻し、動いていた Mawok (MSIX 版か EXE 版か) を起動し直す。パッケージの中から起動した Mawok はコンソールの外で動くので、Ctrl+C では、設定や履歴を戻す前に止める。
- **元の版のデータ**: 外すとパッケージごとの場所 (`LocalCache`) が消える。EXE 版のファイルが無い環境の利用者は、設定・履歴・ログがそこにあるので、外す前に `e2e/.msix-localcache/` へ写し、入れ直した後に戻す。
- **中断されたとき**: 試す前の状態 (入っていたか・StartupTask・動いていた Mawok) を `e2e/.msix-original.json` に控え、後始末が最後まで済んだら消す。Ctrl+C や強制終了で後始末が走らなかったときは、次の回がこの控えを元の状態として戻す (そのとき見える状態を元の状態と取り違えない)。後始末は1つが落ちても残りを試し、落ちたものをまとめて知らせる。
- **常用の設定と履歴**: EXE 版と同じ場所の実物を読み書きするので、E2E と同じ控え (`lib/config.mjs`) でテスト用の設定に替え、終わったら戻す。EXE 版のファイルが無い環境は、`%APPDATA%` と `%LOCALAPPDATA%` の `com.amiiby.mawok` を `….msix-check-held` に名前を変えて退かして作る。何を退かしたかは `e2e/.msix-held.json` に残し、中断されても Ctrl+C ならその場で、強制終了なら次の実行が戻す。
- **読み方**: 通知はポップアップではなく、パッケージの AUMID の通知の履歴 (`ToastNotificationManager.History`) で見る (集中モードではポップアップが出ない)。タスクバーのアイコンの下地は、設定ウィンドウのボタンを撮り、アクセントの色 (`AccentPalette` の8色) の画素がボタンの2%未満であることで見る。タスクバーの背景がアクセントの色に染まっていることもあるので、ボタンの隅の背景に近い色は数えない。下地に載ったボタンは13%ほどがアクセントの色になり、下地なしでは0だった。
- **画面とフォーカスを使う**: トレイのメニューを本物のマウスで開き、Windows の設定とエクスプローラーの窓が前面に出る (開いた窓は閉じる)。

## 注意点

- **設定ファイルの名前の書き方**: 設定ファイルは TOML で、項目名は snake_case、既定と違う値だけが書かれる。テストは画面とのやり取りと同じ camelCase の名前（`textWindowKeys`・`hideTextWindowOnBlur` など）で読み書きし、`lib/config.mjs` が名前を付け替え、書いていない項目を既定値で埋める（既定値は `src-tauri/src/config.rs`・`draft_keys.rs` の写しなので、既定値を変えたら揃える）。TOML の読み書きには `smol-toml` を使う。
- **設定ファイルの後始末**: `%APPDATA%\com.amiiby.mawok\config.toml` を書き換えるテストは、
  前後でバックアップ・復元する (`lib/config.mjs`)。落ちても壊れた設定が残らないよう、必ず
  `test.after` (ファイル単位の後処理) で復元すること。
  同じフォルダーの `.window-state.json` (テキストウィンドウと設定ウィンドウの位置と大きさの記録) も、同じ控えに入れて一緒に戻す。
  設定ファイルを壊すテストがアプリに作らせた `config.broken-….toml` は、テストの前からあったものを残して消す (`tests/config-file.test.mjs`)。
- **ウィンドウの大きさは、下限を見るときだけドラッグで変える**: `SetWindowPos` は最小の大きさを通り抜けて小さくなるので、最小の大きさは右下の角を本物のドラッグで縮めて見る (`lib/input.mjs` の `dragBottomRightCorner`)。位置と大きさの記憶を見るときは、`SetWindowPos` で動かす (`lib/window.mjs`)。
- **中断したときに残るファイルは、次の実行が片付ける**: 実行中は `e2e/.e2e.lock` (同時に2つ
  回さないための排他ロック) と `e2e/.config-backup.json` (config.toml の控え) を置く
  (`lib/config.mjs`、どちらも `e2e/.gitignore` 済み)。
  Ctrl+C (`SIGINT`) やコンソールの窓を閉じたとき (`SIGHUP`。Windows は約10秒後にプロセスを終わらせるが、片付けはそれより早く済む) なら、その場で控えを書き戻してロックを外す (コードは `SIGTERM` も同じく受けるが、Windows では OS から `SIGTERM` は届かない)。
  `node --test` を通すと、Ctrl+C を受けた `node --test` がテストのプロセスをすぐ強制終了し、この書き戻しが途中で打ち切られる (config.toml が空のまま残ったことがある) ので、`run.mjs` はテストファイルを1つずつ `node` で直接回す。中断したら、残りのファイルは回さない。
  タスクマネージャーなどでの強制終了では、その場では書き戻さないので、config.toml はテスト用の設定のまま残る (次の実行までに常用するなら、先に `just e2e` をもう一度回して片付ける)。
  残ったファイルは、次の実行がロックの持ち主のプロセスがもういないことを確かめて取り直し、控えを書き戻してから始めるので、手で消さない。
  手で
  消すのは、控えが壊れている・ロックの中身が読めない・持ち主のプロセスが生きている、と
  エラーで言われたときだけ (その場合も、config.toml の今の中身を確かめてから)。
- **クリップボードは実機の OS のものを使う**: サンドボックス化されていないので、テスト実行中は
  実際のクリップボードの中身が書き換わる。並行して手作業しながら回さないこと。
- **BiDi を無効化する**: WebdriverIO 9 は既定で BiDi セッションを張るが、このアプリでは
  BiDi 経由だと about:blank のまま何も表示していない別 webview に繋がってしまい、実際の
  ウィンドウの内容にも `invoke` にも届かない (`Origin header is not a valid URL` で拒否される)。
  `capabilities` に `'wdio:enforceWebDriverClassic': true` を必ず入れる (`lib/app.mjs` 参照)。
- **テキストウィンドウへの入力にタブ文字を使わない**: WebDriver 経由でテキストエリアに文字を送ると、
  タブ文字は実際の Tab キー押下として扱われ、フォーカスがテキストエリアの外に出てしまう。
  タブ文字の除去そのものは Rust 側の単体テスト (`text::tests::removes_trailing_fullwidth_space_and_tab`)
  で担保する。
- **PowerShell 経由の文字列は `-EncodedCommand` で渡す**: 素朴に `-Command` へ日本語を渡すと
  コンソールのコードページ経由で化けることがある (`lib/os.mjs` 参照)。
- **PowerShell は1つを立ち上げたままにして使い回す**: `runPowerShell` は、テストのプロセスごとに PowerShell を1つだけ起動し、スクリプトを標準入力で流して結果を受け取る (`lib/os.mjs`)。呼ぶたびに起動すると、起動 (0.4 秒ほど) と Add-Type の C# のコンパイルが毎回かかり、draft-buttons ではこれが合計の 9 割近くを占めていた。
  読み込んだ型はプロセスに残るので、同じ名前の型を別の中身で `Add-Type` し直さないこと (エラーになる)。結果は標準出力で返すので、スクリプトの中で `Write-Host` や `[Console]::Out` に書かないこと。
  **ハンドルや座標など毎回変わる値は、スクリプトに埋め込まず `runPowerShell(script, args)` の `args` で渡す** (スクリプトでは `$args[0]` などで読む)。スクリプトは中身ごとに検査され (Windows の AMSI と見られる)、C# のソースを含むスクリプトは中身が変わるたびに 0.5〜1 秒かかる。同じ中身なら結果が覚えられていて数 ms で済む。前にクリックが1回 2 秒を超えていたのは、ハンドルと座標を埋め込んでいたため。
  テストファイルの `after` で終わらせる (`stopPowerShell`) が、落ちても、Ctrl+C で中断しても、強制終了されても、パイプが閉じて PowerShell は自分で終わる。
  **クリップボードに書く (`setClipboard`) のだけは、立ち上げたままの PowerShell を使わず、書くたびに起動する**。書いたプロセスがクリップボードの持ち主のまま残り、メッセージを処理しないので、ほかのプロセス (アプリのコピーも) がクリップボードに書くときに数秒待たされる。アプリは書き終わるまでテキストウィンドウを隠さないので、Ctrl+Enter の後に隠れないように見える。
  貼り付け先のウィンドウと画面を点けておく要求は、終わるまで動かし続けるので、これまでどおり別の PowerShell を起動する。
- **画面がロック・スタンバイ中は回せない**: ロック中はホットキーの送信 (`SendKeys`) がセキュアデスクトップへの入力を拒否されて「Access is denied」で落ち、スタンバイ中は WebView2 がウィンドウを作れない。
  そのため `run.mjs` は、ビルドの前に入力を受けているデスクトップと画面の状態を読み、ロック中か画面が消えていれば、テストを始めずにその旨のメッセージで失敗する (`lib/power.mjs` の `ensureSessionReady`)。
  始めた後は、`SetThreadExecutionState` (`ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED`) で、終わるまで画面を消さずスリープにも入らないようにする。
  画面が消えないので、消えたときに掛かるロックも起きない。PC の電源とロックの設定は変えない。
  Modern Standby の機では `ES_SYSTEM_REQUIRED` だけだと、画面が消えた時点でスタンバイに入ってしまうので、画面ごと点けておく。
  この要求は、要求を出したまま標準入力が閉じるのを待つ PowerShell の子プロセスが持つ (`keepDisplayOn`)。
  テストが落ちても、Ctrl+C で中断しても、`run.mjs` が強制終了されてもパイプが閉じて子プロセスが終わるので、要求は取り消される。
  テストファイルを `node` で直接回すとこの仕組みを通らないので、画面が消えないよう自分で気をつける。
- **トレイのテストは、アイコンがどこに出ていてもよい**: タスクバーに常設で出ていれば直接押し、「非表示のアイコン」の中にいれば、先に「非表示のアイコンを表示する」を押して開いてから押す (`lib/tray.mjs`)。
  常設にするかは実行ファイルごとの設定なので、E2E がビルドする `src-tauri/target/release/mawok.exe` は、常用版 (`%LOCALAPPDATA%\Mawok`) を常設にしていても別扱いで、既定では「非表示のアイコン」の中に入る。
  「非表示のアイコンを表示する」は、時計や音量と同じ AutomationId (`SystemTrayIcon`) なので名前で見分けている。日本語と英語の名前を見るので、ほかの言語の Windows では見つけられない。
  **開いたフライアウトは、テストの後始末で閉じる** (`closeTrayOverflow`)。フライアウトは Explorer 側のものなので、出したメニューを閉じても開いたまま残る。
  トレイのメニューを出すテストは、ファイルをまたいで開きっぱなしを持ち越さないよう、どのファイルでも閉じる (`run.mjs` はファイル名順に回す)。
  Esc を無条件に送るとテキストウィンドウが出ているときにそれを隠してしまうので、開いているときだけ、「非表示のアイコンを表示する」をもう一度押して閉じる (押すたびに開閉が入れ替わる)。
  開いているかは、フライアウトのウィンドウが見えているかで見る。閉じてもウィンドウ自体は残る (実測で、開いているときは visible=True、閉じると visible=False になり、ウィンドウは消えない)。
  Windows 11 と Windows 10 の2つのクラスをまとめて見ているのは、実測で並存しなかったため (Windows 11 build 26200 では `NotifyIconOverflowWindow` のウィンドウは1つも無い)。
  **押すのは `setTrayOverflowOpen(wanted)` の1か所だけ** で、開く側 (`openTrayMenu`) も閉じる側 (`closeTrayOverflow`) もここを通る。押すたびに開閉が入れ替わるので、押す・読む・待つの作法が二手に分かれていると、片方を直すたびにもう片方へ穴が開く (実際に三度続いた)。
  **押す前に、毎回その場で状態を読む。** すでに目的の状態なら押さない。無条件に押すと、閉じ損ねたフライアウトを次のテストが逆に閉じてしまい、閉じた中をアイコンが見つかるまで覗き続けることになる。逆に、判定を待ちのループの外で1回だけにすると、読んだ値が古いときに一度も押さないまま覗き続ける。
  **押した直後は、まだ押す前の状態が読める。** 400ms 置いてから読む。ここを詰めると、開きかけを「まだ閉じている」と読んでもう一度押し、閉じてしまう。
  **1回押しただけでは変わらないことがある** (主に閉じる側で、落ちる場所は回ごとに違う)。なぜそうなるのかは掴めていないので、開くときも閉じるときも、そうなるまで押し直す。
  2回目以降に入ると `[e2e] 「非表示のアイコン」が閉じないので、N 回目を押します` を出す (開く側は「開かないので」)。この行が一度も出ないまま安定しているなら、効いているのは押し直しではなく、押す前に状態を読むようにしたほうだということ。
  それでも目的の状態にならないときは、そのときのウィンドウの状態 (`visible`・`cloaked`・`rect`・前面のウィンドウ) を添えて落とす。推測で書いた原因が二度続けて外れたので、次は実測から始められるようにしてある。
  閉じたあとは、閉じたままであることも確かめる (`expectStays`)。読むのと押すのは同期しておらず、読んでから押すまでにフライアウトが自分で閉じると、押した結果また開くため。
- **トレイと設定ファイルのテストは、警告の文言が日本語である前提**: トレイに出る警告は Rust 側が表示言語から作る。設定ファイルが TOML として読めないときは表示言語も読めないため、OS の地域と言語に従う。
- **IME のテストは Microsoft IME が前提**: 変換中のキーの扱いは、SendInput で `VK_IME_ON` を送ってローマ字を打ち、本物の IME を変換中にして見る (`lib/ime.mjs`)。ほかの IME が既定だと、変換中にならず落ちる。
  **`VK_IME_ON` が届かず、IME がオンにならないことがある**。ウィンドウが IME を受け取れる状態になる前に送ると落ちるとみられる。
  そのまま打つとローマ字が生のまま入り、`変換中の文字が入力欄に出る がタイムアウトまでに条件を満たしませんでした (最後の値: "nihon")` という、3手あとの値の不一致としてしか気づけなかった
  (実測で、全体を回して6回に1回ほど。落ちるのは `settings-ime` の2件目に偏っていた。前のテストの後始末で `turnImeOff()` を送った後、新しいアプリを起動した直後に送る流れ)。
  今は `turnImeOn()` が、送った後に本当にオンになったかを読み (`ImmGetDefaultIMEWnd` + `WM_IME_CONTROL` の `IMC_GETOPENSTATUS`)、なるまで `VK_IME_ON` を送り直す。
  文字を打ち直すのではなく前提が整うのを待つ形なので、IME そのものが壊れているときは隠れず、`IME をオンにできませんでした` で落ちる。
- **IME の開閉は、最前面のウィンドウではなく「フォーカスのあるウィンドウ」から読む**: テキストウィンドウも設定も中身は WebView2 で、入力欄のキーボードのフォーカスは別プロセス (`msedgewebview2.exe`) の `Chrome_WidgetWin_1` にある。
  IME の開閉はそちらが持っているので、最前面の Tauri のウィンドウに `ImmGetDefaultIMEWnd` を掛けて読んでも、オンにした後も 0 のままになる。
  `GetGUIThreadInfo(0)` の `hwndFocus` (スレッド ID に 0 を渡すと最前面のスレッドの情報が返る) を相手にして読む (`lib/ime.mjs` の `readImeOpenStatus`)。

  実測 (`VK_IME_ON` を送る前と後の `IMC_GETOPENSTATUS` の値):

  | 読む相手 | 送る前 | 送った後 |
  | --- | --- | --- |
  | 最前面 (`Tauri Window`、pid=mawok) | 0 | 0 のまま |
  | フォーカス (`Chrome_WidgetWin_1`、pid=msedgewebview2) | 0 | 1 |

  最前面を読む形で書いたときは、IME を使うテストが `IME をオンにできませんでした` で全滅した。
  前面が WezTerm のような単一プロセスのアプリなら最前面でも正しく読めてしまうので、手で試すときは必ずアプリのウィンドウを相手に確かめること。
  E2E だけの話ではなく、アプリ側で IME に触るときにも同じことが起きる。
- **E2E はログイン時の起動の登録に触れることがある**: アプリは起動したときに、登録を設定に合わせる。オンなら、登録があれば E2E が起動した実行ファイルのパスで HKCU の Run に登録し直して `Explorer\StartupApproved\Run` もオンにし (Windows では起動のたびに書き直す)、登録が無ければ初めての起動でだけ登録する (2回目からは設定をオフにそろえ、登録には触れない)。オフなら登録を外す。`beginTestConfig` は autostart を、今の設定によらずオフにする。オンで起動するのは、config.toml のない初めての起動 (draft-first-launch)、settings-autostart が `set_autostart` でオンにするとき、config-file が autostart を書かない設定 (既定はオン) で起動するとき。
  - `just e2e` (run.mjs) は、テスト全体の前後で1度だけ、両方の `Mawok` の値を控えて書き戻し (`os.mjs` の `snapshotAutostartEntry`)、回している間は外しておく (`clearAutostartEntry`)。外しておけば、オフで起動したアプリは登録に触れない。テストファイルごとに控えて戻すと、アプリが登録し直す・外すのと書き戻すのが1回の E2E で約100回くり返され、Windows Defender が Behavior:Win32/Persistence.A!ml と見て常用版を取り除く。
  - run.mjs を通さずに `node` で直接回すときは、`setup.mjs` の `createSuite` がテストファイルごとに控えて戻す (run.mjs からは環境変数 `MAWOK_E2E_AUTOSTART_HELD` で伝え、させない)。常用版が登録されていると、ファイルごとにアプリが外すのと書き戻すのが重なり、Defender に取り除かれたのと同じ形になる。直接回すのは1〜数ファイルに限り、全体は `just e2e` で回す。
  - 控えは `e2e/.autostart-backup.json` にも置き (`e2e/.gitignore` 済み)、config.toml の控えと同じく、Ctrl+C やコンソールの窓を閉じたときはその場で、強制終了されたときは次の実行の始めに書き戻す。控えが読めないとエラーで言われたときは、両方の値を確かめてからファイルを消す。
- **ログイン時の起動とクリップボードの印は、OS 側を直接読む**: 登録は HKCU の `Run` と `Explorer\StartupApproved\Run` を読む (`lib/os.mjs` の `readAutostartEntry`)。
  クリップボードの履歴に残さない印は、本文とは別の「形式」として同じクリップボードに載るので、載っている形式の名前で見る (`getClipboardFormats`。`EnumClipboardFormats` と `GetClipboardFormatName`)。
- **E2E は Windows の外観 (アプリのモード) を一時的に切り替える**: テキストの文字色のテストは、テーマを「OS に従う」にしたときの入れ替わりを見るため、HKCU の `AppsUseLightTheme` を書き換える。書き換える前の値は `e2e/.apps-theme-backup.json` に控え (`e2e/.gitignore` 済み)、終わったら・中断されたら書き戻す。次の実行も、残った控えがあれば先に書き戻す (`os.mjs` の `snapshotAppsTheme`・`recoverStaleAppsThemeIfAny`)。
- **Win+V の履歴に、テストがコピーした項目が入ることがある**: クリップボードの履歴のテストは、設定をオフにしてコピーした項目が履歴に出ることを見て、見た後にその項目を履歴から消す (`removeFromClipboardHistory`)。利用者の履歴の中身は、あるかどうかを読むだけ。履歴がオフの機では、履歴のテストを飛ばす。
- **AI のキーの資格情報は、キーがまだ無い AI サービスでだけ試す**: `actions-command` は、資格情報マネージャーにキーの無い AI サービスを選んで仮のキーを入れ、消えることを見る。本物のキーがあるかもしれないサービスには触らない (全部にあれば飛ばす)。
- **コマンドのアクションのテストは、`more` と `find` を System32 のフルパスで呼ぶ**: E2E のアプリは `just e2e` を回したシェルの PATH を引き継ぐ。開発機の PATH では Git や uutils の同じ名前のコマンドが先に当たり、`more` は標準入力を読み終えても終わらず、`find` は GNU の find になる。既定のアクションの `sort` のように、コマンドの行を変えずに裸の名前で当てたいテスト (`actions-default-sort`) は、フルパスにする代わりに、テストファイルの頭で System32 を PATH の先頭に足す。
- **色は、画面の中で解決した後の値どうしで比べる**: `getComputedStyle` は CSS 変数の色を oklch のまま返すので、テスト側の `#rrggbb` と直には比べられない。
  同じ画面に作った要素にその色を当てて、解決した後の値で比べる (`lib/app.mjs` の `resolveColor`・`readDraftColors`)。
- 壊れたら落ちることを一度は確認してから直す。実装をわざと壊して red になることを見ないと、
  待ち方が甘いテストや条件が緩いテストに気づけない。

## macOS の確認

macOS の WKWebView には WebDriver がないので、macOS だけの作り（フォーカスの戻し方・クリップボードへの書き込み・隠し方など、OS ごとに作りが分かれているところの macOS の側）は、`osascript` の JXA で動かして見る。キーとウィンドウは System Events、画面の中の要素はアクセシビリティの API（AXUIElement）、マウスは CGEvent、ウィンドウの重なりの層はウィンドウサーバーの一覧（CGWindowList）で扱う。両 OS に共通の振る舞いは、Windows の E2E に任せて見ない。

```
just macos-check          # macos/*.test.mjs を全部
just macos-check draft    # macos/draft.test.mjs だけ
just macos-check --restore  # 中断して残った控えから戻すだけ
```

- **ビルドしない**。常用の `/Applications/Mawok.app` を動かす（ほかのものは環境変数 `MAWOK_APP` で指す）。変更を見るときは、先に `just bundle` して入れ直しておく。
- **依存は要らない**（`pnpm install` しなくても回る）。
- **許可**: 回す端末に、アクセシビリティと画面収録の許可が要る（システム設定の「プライバシーとセキュリティ」）。画面収録は、テキストウィンドウの重なりの層を読むのに使う（無いとウィンドウの名前が読めず、最前面のテストが落ちる）。どちらかの許可が無ければ、始める前に止まる。許可は流した大元のアプリに付き、Claude Code は版の番号の名前で出るので、更新のたびにオンにし直す。
- **キーボードとフォーカスを使う**。回している間（全部で十数分）は、キーボードとマウスに触らない。貼り付け先に TextEdit を使うので、TextEdit が動いていると始めずに落ちる。ログイン時の起動の確認（`autostart`）はシステム設定のログイン項目の画面を開いて読み、読んだら終了するので、システム設定が開いていても始めずに落ちる。
- **後始末**: 動いている Mawok を終了し、設定・履歴・ウィンドウの位置の記録（`~/Library/Application Support/com.amiiby.mawok/` の `config.toml`・`history.json`・`.window-state.json`）とクリップボードを `e2e/.macos-backup/` に控えてから始める。終わったら Mawok を終了して戻し、動いていたなら起動し直す。テストが作らせた設定の写し（`config.broken-….toml`）も、戻すときに消す。
  - **ログイン時の起動**: 初めての起動を試すと、ログイン項目が登録される。控えるときに利用者の設定のまま一度起動し、ログイン時の起動が効いているかを読んでおく（登録の状態はほかのアプリから読めないので、ログイン項目が有効でない（システム設定で切った、登録が無い）ときに Mawok がログに書く一行で見分ける。設定ファイルが無ければ、起動すると登録してしまうので、起動せずに効いていないとみなす）。戻すときは、効いていなければオフの設定で一度起動して登録を外し、効いていれば設定ファイルの無い初めての起動で登録し直す（ログイン時の起動の確認は登録を外すが、オンの設定で登録が無いまま起動すると、Mawok は設定をオフにそろえるため）。
  - **中断したとき**: Ctrl+C では後始末が走らず、控えが残る（Mawok はテストの設定のまま）。`just macos-check --restore` で、テストを回さずに戻す。戻さずに次に回したときも、先に戻してから始める。
- **前面のアプリの読み方**: キー入力が Mawok に入るなら、Mawok を前面とみなす。テキストウィンドウはアプリを前面にしないパネルで出すので、`NSWorkspace` でも System Events の `frontmost` でも前のアプリのままになるが、Mawok のプロセスのアクセシビリティの `AXFrontmost` は true になる（2026-10 に macOS 26 で確かめた）。設定を開いたときのようにアプリごと前面になったときは、`NSWorkspace` の `frontmostApplication` で読む（こちらはアプリを終了した後などに古い値を返すことがあるので、ほかのアプリは System Events で読む）。`lib/macos.mjs` の `front()`。

## 育て方

手で確かめる項目に、技術的に自動で見られないものだけが残るよう、E2E を広げていく。

貼り付け先に実際に届くところは、貼り付け先のアプリに Ctrl+V を送り、UI Automation で本文を読んで確かめる (`lib/paste-target.mjs`)。
貼り付け先は、テキストボックスを1つだけ持つ WPF のウィンドウを、PowerShell でテストごとに別のプロセスとして起動する。
メモ帳を使わないのは、Windows 11 のメモ帳が閉じても書きかけのタブを次の起動で戻し、1つのプロセスに複数のタブをまとめるので、まっさらな貼り付け先を用意して確実に片付けるのが難しいため。
WinForms でないのは、複数行のテキストボックスが UI Automation の ValuePattern も TextPattern も持たず、中身を読めないため。
前面にするのも Ctrl+V を送るのも、WebDriver ではなく本物の入力 (`SendInput`、`lib/input.mjs`) で行う。WebDriver の操作は DOM に届くだけで、OS から見たクリックやキー入力は起きないため。
戻り先へのフォーカスは、テキストウィンドウを隠した後の前面のウィンドウ (`GetForegroundWindow`) が貼り付け先であることで見る。

移した項目は、チェックリストから外す。OS ごとに作りが分かれている所 (フォーカスの戻し方、クリップボードの印など) は Windows の作りしか見ていないので、macOS の側を「macOS: 〜」の行として残す。
