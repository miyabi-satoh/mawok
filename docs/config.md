# 設定の置き場

設定・定型文・置き換え辞書・テキストウィンドウの履歴は、設定の置き場のフォルダーにファイルで置く。Mawok は同期の仕組みを持たず、利用者が置き場をクラウドストレージのフォルダーにしたり、dotfiles の管理ツールで扱ったりして同期する。

## 置き場

- 既定は OS 標準のアプリ設定フォルダー（macOS は `~/Library/Application Support/<identifier>/`、Windows は `%APPDATA%\<identifier>\`、Linux は `~/.config/<identifier>/`）。MSIX 版では、ここへ書いたファイルはパッケージの中へ回される（docs/platform.md「Windows の MSIX 版」）ので、画面には回された先のパスを出す。
- 設定の「同期」で、別のフォルダーを選べる。Windows では symlink を張るのに権限が要るので、symlink だけに頼らない。
- 置き場を替えるとき:
  - 替えた先に設定のファイルがあれば、そちらを使うか、このデバイスの設定で上書きするかを利用者に選んでもらう。そちらを使うなら、読めないファイルがあるときは替えない。
  - このデバイスの履歴は、替えた先の履歴に混ぜて持っていく。
  - 前の置き場のファイルは消さない。ほかのデバイスが使っていることがあるため。
- 選んだ置き場のフォルダーが無いとき（クラウドストレージのドライブがまだつながっていない・外れた・フォルダーを消した など）は、フォルダーを作らず、置き場に何も書かない。既定のままの設定で書くと、つながった後に同期先のファイルを既定で上書きし、外れたドライブの場所に普通のフォルダーを作ると、つながった後のフォルダーと別物になるため。
  - 起動のときと、書く前に確かめる。起動のときに無ければ、既定の設定で動かす。
  - 見つからないことをトレイに出し、画面からの設定の変更は保存できなかったと返す。デバイスの手元に置くもの（ログイン時の起動）は変えられる。
  - 履歴は、無い間に消した・覚えたものを動いている間だけ控え、現れたら書く（消したものは消した時刻で書く）。現れる前に終了すると、控えは消える。毎日のバックアップは書かない。
  - 5 秒ごとに見て、現れたら読み直して見張りを始める。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `settings.toml` | 設定の項目。項目名は snake_case（`text_window_always_on_top` など） |
| `snippets.toml` | 定型文の並び（`[[snippets]]`） |
| `replacements.toml` | 置き換え辞書の並び（`[[replacements]]`） |
| `history/<デバイス>.json` | テキストウィンドウの履歴（「履歴」） |

- 種類ごとにファイルを分ける。定型文だけを人と分け合え、2台で別の種類を直したときにぶつからないため。
- **既定と違う値だけを書く。** 既定のままの項目は書かず、設定画面で既定に戻した項目は消す。版を上げて既定値を変えたときに、変えていない人へ新しい既定値が届くようにするため。
- ホットキーとキー操作は、`[hotkey]`・`[text_window_keys.<OS>]` の OS ごとの欄に分ける（OS の名前は `macos`・`windows`・`linux`）。キーの名前が OS で違い、クラウドストレージにはマシンごとに書き分ける仕組みが無いため。自分の OS の欄だけを読み書きする。
- 設定画面での変更は、すぐにファイルに書いて反映する。書くときは:
  - 手で書いたコメント・並び・知らない項目は残し、変えた項目だけを書き換える（`toml_edit`）。定型文と置き換え辞書は、変わった行だけを書き換える。知らない項目は、新しい版が書いたものや手で書いたものとして扱う。
  - 中身が変わらないファイルは書かない。置き場を同期していると、書くたびにほかのデバイスへ送られ、衝突のもとになるため。
  - 一時ファイルに書いてから差し替える。置き場のファイルが symlink なら、その先へ書く。stow などで張った symlink を、差し替えで普通のファイルにして壊さないため。
  - 読めないファイル（書きかけ・形が合わない）は書き換えず、画面に保存できなかったことを返す。手で直している途中のものを、画面からの変更で消さないため。

## 読むとき

- 無いファイルは、書いていない（既定のまま）として扱う。初めての起動では何も無い。
- 読めない値（型が合わない、範囲の外など）は既定のままにし、ログにだけ出す。置き換え辞書・定型文は、読めない行だけを読み飛ばす。
- 知らない項目は読み飛ばす。新しい版が書いた項目を、古い版で開いても動くようにするため。
- 読めないファイルは、そのファイルの項目を前に読めた設定（起動のときは既定）のままにし、読めないことをトレイに出す。直して保存すれば読み直し、トレイの知らせも消える。

## ほかで変わったとき

- 置き場のフォルダーと履歴のフォルダーを見張る（`notify`）。設定のファイルが symlink なら、その先のフォルダーも見張る。先のファイルを直すと、先のフォルダーにだけ知らせが来るため。先のファイルは名前が違うこと（`ln -s ~/dotfiles/mawok.toml settings.toml`）があるので、名前でなくパスで選ぶ。symlink を張った・張り替えたら、新しい先を見張り直す。
- 変わってから 0.5 秒落ち着くのを待って読み直す。エディターの保存やクラウドストレージの書き込みは、何回かの変化になるため。
- 読んだ設定は、画面から変えたときと同じ検査と反映を通す。OS に断られて当てられなかった項目（ホットキー・最前面）は今の値のままにし、ファイルには書き戻さない。設定画面には、持っている写し（行・打って直す欄）を写し直させる。
- 自分で書いた変化の知らせも届くが、読んだ設定が今と同じなら何もしない。
- 2台で同じファイルを書いたときは、ファイルごとに後から書いたほうが残る（クラウドストレージによっては、衝突したコピーができる）。食い違いはオフラインの2台で同じファイルを変えたときにしか起きず、消えた値は毎日のバックアップから戻せるため。

## 履歴

- 各デバイスは自分のファイル（`history/<デバイスの見分け>.json`）だけを書き、読むときに、置き場のすべてのデバイスのファイルを混ぜる。コピーのたびに書くので、1つのファイルを2台で書くとすぐにぶつかるため。ほかのデバイスのファイルは書かない。
- ファイルの中身: `{ "version": 2, "entries": [{ "text": <本文>, "at": <覚えた時刻。UNIX のミリ秒で、1 以上> }], "cleared_at": <履歴を消した時刻。消していなければ 0> }`。`entries` は古い順。unix では所有者だけが読めるようにする。
- 混ぜ方:
  1. `cleared_at` は、すべてのファイルの最大にする。
  2. すべての `entries` を合わせ、`at` が `cleared_at` 以下のものを落とす。どこかのデバイスで履歴を消したら、それより前に覚えた履歴はどのデバイスの分も見せないため。
  3. 同じ本文は、`at` が大きい方の1つにする。
  4. `at` の古い順に並べ、新しい方から 100 件を残す。`at` が同じ履歴は、本文の順に並べる。
  - 混ぜた結果は、ファイルを読む順に依らない。
- 画面に出すのは、混ぜた結果をそのデバイスの履歴の件数（`text_history_size`）に切り詰めたもの。自分のファイルには、混ぜて切り詰めた結果を書く。次に画面から保存するときに、混ぜた履歴と照らして時刻を付けるため。
- ほかのデバイスのファイルが変わったら、混ぜ直して自分のファイルに入れ、テキストウィンドウに読み直させる。履歴をたどっている途中なら、たどり終えてから入れ替える。テキストウィンドウが読み直す前の保存で、混ぜた履歴を上書きしない。
- 時刻:
  - 時刻は、画面から保存するときに付ける。画面は本文の一覧だけを持つので、前に保存した履歴の末尾と、届いた一覧の先頭が重なるいちばん長い所を、引き続きある本文とみて前の時刻を保ち、その後ろを新しく覚えた本文として今の時刻を付ける。
  - 新しく覚えた本文の時刻は、消した時刻と、引き続きある本文の時刻より後にする（同じ回に覚えた本文は 1 ミリ秒ずつずらす）。時計が戻っている・ほかのデバイスの時計が進んでいるときに、今覚えた本文が、消したはずの履歴として落ちたり、古い方へ入ったりしないため。
  - 時刻の無い前の形のファイルは、読むときに、ファイルの更新時刻から古い順に 1 ミリ秒ずつさかのぼった時刻を付ける。自分のファイルなら、その場で今の形で保存し直す。
- 履歴を消したとき（件数を 0 にしたときを含む）は、消した時刻を自分のファイルに置く。件数が 0 のままの起動では、消す履歴があるときだけ置く。起動のたびに置くと、ほかのデバイスがその後に覚えた履歴まで消すため。
- 自分のファイルが読めなければ、同じフォルダーの `<名前>.broken-YYYYMMDD-HHMMSS.json`（時刻は UTC）へ写してから消す。写しは混ぜない。ほかのデバイスのファイルが読めなければ（書きかけを読んだなど）、ログに出して飛ばす。

## デバイスの手元に置くもの

OS 標準のアプリのデータのフォルダー（macOS は `~/Library/Application Support/<identifier>/`、Windows は `%LOCALAPPDATA%\<identifier>\`、Linux は `~/.local/share/<identifier>/`）の `device.json` に置く。置き場を替えても動かず、既定の置き場を dotfiles などで同期しても、ほかのデバイスに渡らないようにするため（macOS だけは既定の置き場と同じフォルダーになる）。

- デバイスの見分け（ランダムな 16 進）。履歴のファイルの名前に使う。
- 選んだ置き場。
- ログイン時の起動。OS への登録とともにデバイスごとに決まるもので、ほかのデバイスに持っていかないため。設定のファイルを読み直しても、OS への登録にそろえた今の値を保つ。
- `device.json` が無ければ初めての起動として、テキストウィンドウを一度出す。置き場にほかのデバイスの設定があっても、このデバイスで初めて起動したなら使い方を伝えるため。

## バックアップ

置き場の項目（既定と違う値だけ）を、`device.json` と同じフォルダーの `backups/` に UTC の `YYYYMMDDTHHMMSSZ.json` という名前で書く。置き場に置くと、同期したほかのデバイスのバックアップと混ざるため。

- 書くとき:
  - 毎日。起動したときと、その後は1時間ごとに見て、いちばん新しいバックアップから1日たっていれば書く。常駐したまま日をまたぐので、起動のときだけでは足りない。
  - 設定の「このアプリについて」の「今すぐバックアップ」。
  - バックアップから戻す直前。戻したことを戻せるようにするため。
- いちばん新しいバックアップと同じ中身なら書かない。30 日より古いものを消すが、新しい方から 10 件は残す（VS Code の設定同期の控えと同じ期間と件数）。
- 戻すときは、残しているものを新しい順にすべて並べ、それぞれ戻すと今の設定から変わる所（変わるもの・消えるもの・戻るもの）を添える。行は ID を持たないので、置き換え辞書は置き換える前の文字列、定型文は見出しと本文が同じ行を同じ行とみる。今と同じ中身のバックアップは選べない。
- 戻すと、ログイン時の起動は今のまま残し、ほかの項目と行をバックアップの値にして、置き場のファイルに書く。反映はほかで変わった設定を読んだときと同じ検査と経路を通し、OS に断られて反映できなかった項目（ホットキーなど）は今の値のまま残して、一部を戻せなかったことを伝える。
