# 設定ファイル

- 形式は TOML で、ファイル名は `config.toml`。置き場所は OS 標準のアプリ設定フォルダ（macOS は `~/Library/Application Support/<identifier>/`、Windows は `%APPDATA%\<identifier>\`）。
- 項目名は snake_case（`text_window_always_on_top` など）。項目と既定値の一覧はマニュアル（`docs/manual/`）にある。
- 項目: ホットキー、テキストウィンドウのキー操作（`text_window_keys`）、ログイン時の自動起動、表示言語、テーマ、テキストウィンドウを常に最前面に表示するか、ほかのアプリに移ったらテキストウィンドウを隠すか、テキストウィンドウにボタンを表示するか、履歴の件数、末尾の整え、置き換え辞書、定型文、アクション（AI サービス・モデル・同意した AI サービス・アクションの並び。キーは書かない）、句読点の統一、全角・半角の統一（種類ごと）、クリップボードの履歴に残さない、テキストのフォントと文字の大きさ、テキストの文字色（ライトとダーク）、入力欄の案内、同じアカウントで見つけた機器。
- **既定と違う値だけを書く。** 既定のままの項目は書かず、設定画面で既定に戻した項目は消す。版を上げて既定値を変えたときに、変えていない人へ新しい既定値が届くようにするため。初めての起動で作るファイルは空になる。
- 置き換え辞書・定型文・`devices` のような並びは、`[[replacements]]` のような表の並びで書き、行ごとにすべての項目を書く。手でインラインの配列（`replacements = [{ … }]`）で書いた並びも読み、書き換えるときもインラインの配列のまま書く。並びが空になったら、項目ごと消す。
- 設定画面での変更は、すぐに設定ファイルへ保存して反映する。
  - **保存のたびに設定ファイルを読み直し、変わった項目だけを書き換える。** 手で書いたコメント・並び・空行と、変えていない項目の書き方は残す。起動した後に手で直したほかの項目も残る（反映は再起動で）。
  - 消した項目の前の行に書いたコメントは、項目と一緒に消える。
  - 並びは、変えていない先頭と末尾の行をそのまま残し、変えた行だけを書き換えるので、変えていない行のコメントは残る。インラインの配列でも同じく、キーの前のコメント、変えていない行とその前後のコメントを残す。足した行は隣の行と同じ字下げで書く。書き換えた行の中（`{ … }` の内側）に書いたコメントは残らないことがある。最後の行の後ろに書いたコメント（カンマの前でも後でも）は、末尾に行を足したり消したりすると隣の行に付いて見える。
  - 改行は LF で書く。CRLF のファイルを保存すると、ファイル全体が LF になる（TOML としてはどちらも読める）。
- 設定ファイルを直接編集した内容は、アプリの再起動で反映する。
- 知らない項目は読み飛ばし、ログにだけ出す（トレイには出さない）。表の見出し（`[text_window_keys]` など）の後ろに書いた項目は、その表の中の項目として読まれることに注意（ファイルの末尾に足した項目が、最後の表に入って読み飛ばされる）。
- 空のファイルは、すべて既定値として読む。
- 直接編集して壊した場合の扱いは、壊れ方によって違う。
  - **TOML として読めない**（引用符の閉じ忘れ、値の書き忘れ、同じ項目を2回書いた、UTF-8 でない文字コード（Shift_JIS など）で保存したなど）: 設定全体が既定値に戻り、トレイに警告（読めない理由。TOML の書き間違いなら行と桁も。UTF-8 でないときは文字コードの問題だと分かる理由だけで、行と桁は出ない）が出る。
  - **TOML としては読めるが、項目の型が合わない**（文字列のところに数値や真偽値、選択肢にない値、文字色の `#rrggbb` として読めない値など）: **その項目だけを既定値に直して読み進め**、直した項目を設定ファイルの項目名でトレイに出す（`theme`、`replacements[3]` など。辞書の行は 0 から数える）。多いときは先頭の3件と残りの件数にし、すべてをログに残す。置き換え辞書と定型文とアクションは、型の合わない行だけを読み飛ばし、残りの行を使う。
    - テキストウィンドウのキー操作は、操作ごとに読む（`text_window_keys.copy` など）。
    - 例外として、文字の大きさの範囲の外（10〜32）や小数は、値としては読めるので、知らせずに範囲内の整数へ収める。TOML では整数と小数が別の型だが、どちらも数として読む。履歴の件数も、上限（100）を超える値や小数は同じく収める。ただし負の数は、打ち間違いとみて型の合わない値と同じく既定値（50）に直して知らせる。0 に収めると、履歴を使わない設定として起動したときにディスクの履歴を消してしまうため。
  - どちらの場合も、読み込んだ時点では設定ファイルを書き換えない。直して起動し直せば元に戻る。
  - この状態で設定画面から何かを変えると、**最初の保存の前に、元のファイルを同じフォルダーの `config.broken-YYYYMMDD-HHMMSS.toml`（時刻は UTC）へ写してから上書きする**。直した項目の元の値や、TOML として読めなかったときの辞書を失わないため。写したファイルは消さない。写せなければ保存せず、設定画面に理由を出す。
    - 型の合わない項目があったときは、直した項目だけを書き直し、ほかの項目のコメントは残す。TOML として読めなかったときは、新しいファイルとして書く。
    - 起動したときは読めたが、その後に手で壊されて読めなくなっていたときも、同じく写してから新しいファイルとして書く。
  - 保存できたら、トレイの警告を「元の設定ファイルを写した」という知らせ（写した先のファイル名）に差し替え、次に起動し直すまで出す。
