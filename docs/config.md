# 設定の置き場

- 設定は SQLite のファイル `settings.db` に置く。置き場所は OS 標準のアプリ設定フォルダ（macOS は `~/Library/Application Support/<identifier>/`、Windows は `%APPDATA%\<identifier>\`、Linux は `~/.config/<identifier>/`）。中身を変えるのはアプリだけで、手で書く使い方はしない。
- 表は3つで、設定を書くのと同じトランザクションで同期の oplog も書く（docs/sync.md「手元の記録」）。
  - `settings`: 項目名と、値（JSON）。
  - `sync_outbox`: 手元で変えて、まだ窓口へ送っていない同期の項目と、最後に変えた時刻（oplog）。
  - `meta`: 同期の記録など、設定でないもの。
- 項目名は snake_case（`text_window_always_on_top` など）。同期の項目（docs/sync.md「同期する単位」）と同じ名前を使う。
- **既定と違う値だけを書く。** 既定のままの項目は書かず、設定画面で既定に戻した項目は消す。版を上げて既定値を変えたときに、変えていない人へ新しい既定値が届くようにするため。初めての起動では表は空になる。
  - テキストウィンドウのキー操作は、既定と違う操作だけを書く。AI サービスごとのモデルは、既定のモデルと違うものだけを書く。
  - 定型文は、既定の定型文のままなら書かず、利用者が変えたら、全部消して空になっても書く。
  - 置き換え辞書・定型文は、行の並びを1つの値にし、行ごとに同期で見分ける小文字16進32文字の `id` と、ほかのデバイスと同期するかの `sync` も書く。
- 設定画面での変更は、すぐに保存して反映する。

## 読むとき

- 読めない値（型が合わない、範囲の外など）は既定のままにし、ログにだけ出す。置き換え辞書・定型文は、読めない行だけを読み飛ばす。
- 知らない項目は読み飛ばし、書き換えない。新しい版が書いた項目を、古い版で開いても動くようにするため。
- 行の `id` が無いか正しくないときは、次に同じ行を見分けられるよう、新しい ID を振って書き戻す。
- `settings.db` が SQLite のファイルでないか壊れているとき（SQLite が `SQLITE_NOTADB`・`SQLITE_CORRUPT` を返したとき）は、元のファイルを同じフォルダーの `settings.broken-YYYYMMDD-HHMMSS.db`（時刻は UTC）へ写してから、既定の設定で作り直す。写した先をトレイに出す（次に起動し直すまで）。作り直せもしないときと、壊れてはいないのに開けないとき（ロック・権限・入出力の失敗）は、ファイルに手を付けず、保存しないまま既定の設定で動かし、保存できないことをトレイに出す。時間をおけば開けることがあるファイルを、作り直して失わないため。

## バックアップ

置き場の項目（既定と違う値だけ）を、同じフォルダーの `backups/` に UTC の `YYYYMMDDTHHMMSSZ.json` という名前で書く。

- 書くとき:
  - 毎日。起動したときと、その後は1時間ごとに見て、いちばん新しいバックアップから1日たっていれば書く。常駐したまま日をまたぐので、起動のときだけでは足りない。
  - 設定の「このアプリについて」の「今すぐバックアップ」。
  - バックアップから戻す直前。戻したことを戻せるようにするため。
- いちばん新しいバックアップと同じ中身なら書かない。30 日より古いものを消すが、新しい方から 10 件は残す（VS Code の設定同期の控えと同じ期間と件数）。
- 戻すときは、残しているものを新しい順にすべて並べ、それぞれ戻すと今の設定から変わる所（変わるもの・消えるもの・戻るもの）を添える。今と同じ中身のバックアップは選べない。
- 戻すと、デバイスごとに決める項目（ログイン時の起動・AI の了解・同期する種類のスイッチ・設定の同期から外した項目）は今のまま残し、ほかの項目と行をバックアップの値にする。
  - 戻した値は、手元で変えた値として oplog に積む。同期していれば、ほかのデバイスにも届く。
  - 今が定型文の行を持っていて、バックアップが既定の定型文のままなら、既定の定型文を行として戻す。既定のままという表現に戻すと行の項目が無くなり、同期している行を消したものとして、ほかのデバイスからも消すため。
  - 今とバックアップで `id` だけが違い中身が同じ行は、今の `id` をバックアップの並びの位置へ読み替えて、同じ行として扱う。同じ中身の行を消して足すと、同期している行がほかのデバイスから消えるため。
  - 反映は同期で届いた値と同じ検査と経路を通す（docs/sync.md「1回の同期」）。OS に断られて反映できなかった項目（ホットキーなど）は今の値のまま残し、一部を戻せなかったことを伝える。
