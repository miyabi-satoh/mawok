# 設定と履歴の同期

Pro の Mawok は、同じアカウントにサインインして同じ同期のパスワードを入れたデバイスの間で、設定とテキストウィンドウの履歴を同期する。窓口（`docs/account-server.md`「同期」）には暗号文と、パスワードで包んだ鍵だけを置く（「同期のパスワード」）。

同期が動くのは、Pro で、同期の鍵の状態が `Ready` のとき（「同期のパスワード」）。同期する種類は、設定の「アカウント」のスイッチでデバイスごとに選ぶ。どれも既定はオンで、スイッチ自体と `sync_excluded_settings` は同期しない。

| 種類 | 設定の項目 | 窓口の項目 |
| --- | --- | --- |
| 設定 | `sync_settings` | キー操作以外の `s_…` |
| キー操作 | `sync_keys` | `s_hotkey_<os>`・`s_text_window_keys_<os>` |
| 置き換え辞書 | `sync_replacements` | `r_…`・`o_replacements` |
| 定型文 | `sync_snippets` | `n_…`・`o_snippets` |
| 履歴 | `sync_history` | collection `history` |

設定は、`sync_excluded_settings` に設定の項目名を入れると、その項目だけを外せる。知らない名前は残すが無視する。キー操作は組で検査するため、個別には外せない。

止めた種類・項目は読み書きせず、窓口にある項目を消す・外した印を書く処理もしない。止めても、窓口の写しと、ほかのデバイスは変えない。すべての種類がオフなら通信しない。

- 止めた種類・項目の記録は消さない。止めている間は、まとまりごとに、読まずに置いてある位置（止めたときの `since`）を記録に置き、戻した回はそこから読む。まとまりは、6つの種類と、個別に外した設定の項目1つずつ（窓口の id。`s_theme` など）。読む位置はまとまりで分かれていないので、置かないと、止めている間に進んだ `since` より前の変更を取りこぼす。戻って読んだ項目のうち、もう見たものは `seq` で飛ばす（「1回の同期」）。
  - 位置は、スイッチか除外を変えたときと起動のとき（変えた後、記録を置く前にアプリが止まった場合のため）に、通信せずに記録に置く。変えた後の同期の回に任せると、全部オフの間（通信しない）と窓口につながらない間は置かれず、戻した回が、止めていたことを知らないため（履歴は「混ぜ方」）。記録が無い（一度も同期していない）デバイスには置かない。
  - 記録を保存するときは、そのとき止めているまとまりに位置が無ければ置く。通信の間に止められたときに、通信の前の記録から作った結果で、位置を上書きしないため。
  - この回に読み始める位置は、`since` と、今は止めていないまとまりに残っている位置の、最小。
  - 位置は、そのまとまりを読んだ回に外す。結果を捨てた回と失敗した回は残る。個別に外した項目の位置は、種類「設定」のオン・オフに依らず置き（種類「設定」を止めている間に外した項目は、種類を止めたときの位置で置く。そのときから読んでいないため）、除外をやめても、種類「設定」がオフの間は残す（まだ読んでいないため）。履歴の位置は、オンに戻して履歴が揃った回に外す。揃わなかった回（読み直しや書き込みの失敗など）は残し、次の回もオンに戻した回として扱う。
- 「初めての同期」として合わせるかは、項目ごとに決まる。記録が無いとき、または、その項目のまとまり（種類と、個別に外した項目なら自分自身）を一度も読んでいないとき（位置が 0。初めて同期した回に止めていたまとまりは、位置を 0 にして記録を作る）。回の最初に前の記録から決め、`conflict` を受けた当て直しでも変えない。
- スイッチか除外を変えたら、すぐに同期する。
- 止めている間に手元で変えた項目も oplog に積み、オンに戻した回に送る（「手元の記録」）。

## 同期のパスワード

項目の暗号に使う鍵（同期の鍵。32 バイトの乱数）は、同期を始めたデバイスが作り、利用者が決める同期のパスワードで包んで窓口に置く。窓口にはパスワードも鍵そのものも渡さないので、運営者は中身を読めない。パスワードを忘れると鍵は取り戻せないので、同期をリセットして新しい鍵で始め直す（各デバイスの設定と履歴は残る）。復旧キーとパスワードのヒントは置かない。

- 置き場: OS の資格情報管理の `mawok-account` の項目の `key` の欄（小文字の16進）。トークンと同じ項目に置き、設定の置き場・`pro-state.json`・ログには置かない。起動のたびにはパスワードを聞かない。サインアウトで消す。
- 用途ごとの鍵: 同期の鍵から HKDF-SHA256 で導く。info は `mawok key id v1`（窓口に渡す見分けの `key_id`。小文字の16進64文字）と `mawok sync v1`（「暗号」）。
- 包み方: パスワード（UTF-8。正規化しない）から Argon2id（v0x13・メモリー 64 MiB・繰り返し 3・並列度 4・salt 16 バイト・出力 32 バイト）で鍵を作り、XChaCha20-Poly1305（24 バイトの nonce・関連データ `mawok sync key v1`）で同期の鍵を包む。パラメーターは RFC 9106 の2つ目の推奨（メモリーの限られる環境向け）と同じ。
- 窓口に置く形: JSON の `{ "v": 1, "kdf": "argon2id", "m": 65536, "t": 3, "p": 4, "salt": …, "nonce": …, "key": … }`（後ろの3つは base64）を、文字列のまま置く。開くときは、置いてある salt とパラメーターを使う。パラメーターは、この版が書く値を下限、メモリー 256 MiB・繰り返し 8・並列度 8 を上限とし、外れる値は開かずに断る。窓口から軽い値を押し付けられて、漏れた包んだ鍵の総当たりが安くならないため、重い値でデバイスのメモリーや時間を使い切らせないため。salt は 16 バイトちょうどにする。
- パスワードの正しさは、包んだ鍵が開くかで見る。長さは 8 文字以上（コードポイントで数える）で、値は `src-tauri/src/sync_key.rs` の `MIN_PASSWORD_CHARS` の1つにまとめ、画面へ書き出す。

鍵の状態は、Pro を確かめた直後に、`GET /v1/sync/key` と手元の鍵を照らして決める。`Ready` でないときは同期の記録を消す（前の鍵の記録は、揃った後の鍵では使えないため）。

| 状態 | 条件 | 設定の「アカウント」の同期の所 |
| --- | --- | --- |
| `None` | Pro でないか、サインインしていない。窓口へつながらず手元にも鍵がないときもこの状態。 | 同期する種類のスイッチなど |
| `NotStarted` | 窓口に包んだ鍵が無い。前の版が置いた、包んだ鍵の無い `key_id` も含む（パスワードを入れても揃えられないため）。 | 「同期のパスワードを作成」 |
| `NeedsPassword` | 窓口に包んだ鍵があり、手元に鍵が無いか、手元の鍵の `key_id` が違う。 | 「同期のパスワードを入力」 |
| `Ready` | 手元の鍵の `key_id` が窓口と同じ。窓口へつながらず、手元に鍵があるときもこの状態。 | 同期する種類のスイッチなどと「同期のパスワード」 |

- 始める（「同期を開始する」）: 新しい鍵を作って包み、資格情報管理に置いてから `POST /v1/sync/start` に `key_id` と包んだ鍵を送る。窓口に断られたら、資格情報管理の鍵を置く前に戻す（先に窓口が受け付けると、手元に置けなかったときに、窓口だけが新しい鍵になるため）。受けたか分からない失敗（つながらない・窓口の不調）では、窓口の今の `key_id` を読み、新しい鍵なら受けていたとして続け、違うか読めなければ前の鍵に戻す。受け付けられたら「初めての同期」から始める。窓口に包んだ鍵がもうあれば（ほかのデバイスが先に始めた）409 が返るので、鍵の状態を読み直して「同期のパスワードを入力」へ移る。
- 加わる: 包んだ鍵をパスワードで開き、`key_id` が窓口と同じなら資格情報管理に置く。
- 変える: 今のパスワードで開けたら、同じ鍵を新しいパスワードで包み直し、`PUT /v1/sync/key` で置き換える。`key_id` は変わらないので、ほかのデバイスは入れ直さない。開いた後にほかのデバイスがリセットしていたら（409）、置き換えない。
- 窓口の状態が欄を出したときから変わっていた（ほかのデバイスが始めた・リセットした・Pro が終わった）ときは、エラーを出さずに鍵の状態を読み直し、今の状態の欄へ移す。
- リセット（「同期をリセット...」と「パスワードをお忘れですか？」）: 確かめた後に新しいパスワードを作り、「始める」と同じ順で `POST /v1/sync/reset` に送り、新しい鍵で窓口の写しを始め直す。窓口の写しが消えるのは作り終えたときで、作るのをやめれば何も変えない。ほかのデバイスは `NeedsPassword` になり、新しいパスワードを入れるまで同期が止まる。

## 同期する単位

窓口の1項目は `collection` と `id` で見分ける。履歴は下の「履歴の同期」。設定の同期は、全部を collection `settings` に置き、`id` の頭の1文字で種類を分ける（窓口の `id` は英数字と `_`・`-` の 64 文字までで、collection は `settings` と `history` だけのため）。

| 種類 | 窓口の id | 中身 |
| --- | --- | --- |
| 設定の項目 | `s_<項目名>` | その項目の値 |
| 置き換え辞書の行 | `r_<行の id>` | その行（`id` と `sync` を除く） |
| 定型文の行 | `n_<行の id>` | 同上 |
| 並び | `o_replacements`・`o_snippets` | 同期する行の `id` の並び |

設定の項目は次のとおり。

- どのデバイスでも同じ値にする項目: `language`・`theme`・`text_window_always_on_top`・`hide_text_window_on_blur`・`show_text_window_buttons`・`text_history_size`・`trim_trailing_whitespace`・`punctuation_style`・`alphabet_width`・`digit_width`・`space_width`・`symbol_width`・`katakana_width`・`exclude_from_clipboard_history`・`text_font_family`・`text_font_size`・`text_color_light`・`text_color_dark`・`input_guidance`・`ai_service`・`ai_models`。
  - 全角・半角を揃える設定は、まとめた1項目にせず、文字の種類ごとの項目にする。設定の画面の1行を、同期する・外す1単位に揃えるため。
- OS ごとに分ける項目: `hotkey`・`text_window_keys`。id の後ろに `_macos` か `_windows` を付け（`s_hotkey_macos` など）、自分の OS の項目だけを読み書きする。キーの名前が OS で違うため。`text_font_family` は分けない。font-family の並びで、その OS に無い書体は次の候補に落ちるため（VS Code の `editor.fontFamily` も OS をまたいで同期する）。
- 同期しない項目: `autostart`・`ai_consent`・`ai_base_url`・`sync_settings`・`sync_keys`・`sync_replacements`・`sync_snippets`・`sync_history`・`sync_excluded_settings`・`yielded_draft_keys`。AI サービスのキー（OS の資格情報管理）、アカウントと Pro の状態、ウィンドウの位置も同期しない。デバイスに固有か、デバイスごとに本人が決めるものであるため。

行（置き換え辞書・定型文）は、`sync` が true の行だけを同期する。`sync` が false の行は、同じ `id` の項目が窓口から届いても、中身も `sync` も変えない。同期から外した行を、手元の項目として保つため。

- 既定の定型文のまま（docs/config.md）なら同期しない（行も並びも書かない）。編集して置き場に書かれたときから同期する。既定の定型文の `id` は、定型文ごとに決まった値にする。2台で別々に編集しても、同じ定型文が2つに増えないため。
- 既定の定型文のうち、コマンドの見本（`@sh sort`）は `sync` を false にしておく。文字コードの既定が OS で違うため。
- 既定の定型文のままのデバイスに定型文の行か並びが届いたら、同期しない既定の定型文だけを設定に書き出し、同期する行は届いたものだけにする。届いた行を、書き出した既定の値と比べない。既定の値は表示言語で違うので、比べると手元を変えていないのに食い違いになるため。ほかのデバイスで消した既定の定型文を、戻さないためでもある。
- 既定で同期する既定の定型文を、同期しない行として初めて設定に書いたデバイスは、その `id` に同期から外した印を書く。窓口にその `id` の項目がすでにあれば印は書かず、手元の行を同期しないまま残す（ほかのデバイスが同期している行を外さないため）。印が届いた既定の定型文のままのデバイスは、印が届いた時点で既定の定型文を設定に書き出し、その既定の定型文を `sync` が false の行として残す。同じ回に届いた項目では、印を行と並びより先に入れる。印が無いと、窓口の上で「消した」と見分けられず、外しただけの定型文がほかのデバイスから消えるため。
- 並びは、並びの項目（`o_…`）で揃える。同期しない行は、手元で直前にある行の後ろに置いたままにする。届いた並びに、手元で同期する行として持っていない `id`（同期しない行・手元に無い行）があれば、それを除いた並びで揃ったとみなす。除かないと、その行を同期するデバイスと並びを書き戻し合うため。

## 暗号

- 鍵: 同期の鍵から HKDF-SHA256（info は `mawok sync v1`）で導いた 32 バイト。
- 方式: XChaCha20-Poly1305。項目ごと・書くたびに 24 バイトの乱数の nonce を作る。
- 関連データ: `key_id`・`collection`・`id` を、それぞれ長さ（4 バイトのビッグエンディアン）を前に付けてつないだもの。別の項目の暗号文を差し替えられないため。
- 窓口に渡す `data`: nonce と暗号文をつないで base64 にしたもの。
- 平文: JSON の `{ "v": 1, "value": <値>, "at": <時刻> }`。行を同期から外したことを伝えるときは `{ "v": 1, "detached": true, "at": <時刻> }`。`at` は、書いたデバイスでその値にした時刻（UNIX のミリ秒、oplog の時刻）で、食い違ったときに後から変えた方を残すのに使う（「食い違い」）。変えた時刻の分からない値（初めての同期で書いた、手元で変えていない値など）は `at` を省き、0 として扱う。

復号できない項目と、知らない `v`・知らない項目名・形の合わない値は、読み捨てる（新しい版が書いた項目を、古い版が壊さないため）。読み捨てた項目は書き戻さない。

## 手元の記録

設定の置き場（`settings.db`。docs/config.md）に置く。

- oplog（表 `sync_outbox`）: 手元で変えて、まだ窓口へ送っていない項目（窓口の id）と、最後に変えた時刻。設定を保存するのと同じトランザクションで積む。保存の前と後の設定を窓口に置く粒度で比べ、違う項目を積む。同期で届いた値を入れた保存では積まない。同期を止めている種類の項目も積む。
  - 窓口へ書けた項目と、窓口の値を手元に入れた項目は、oplog から外す。外すのは、そのとき見ていた時刻より後にまた変えていないときだけ。通信の間に変えた値を、送ったものとして落とさないため。
- 同期の記録（表 `meta`）:
  - `key_id` と、次に読む位置（`since`）。
  - 項目ごとに、最後に窓口と揃ったときの `seq` と、そのときの平文の SHA-256。SHA-256 は、混ぜて揃える項目（並び・履歴）が、手元を変えたかを見分けるのに使う。
  - 窓口で消えた・同期から外れた項目の `seq`。同じ id をもう一度書くときの `base_seq` に使う。
  - 止めている種類・個別に外した設定を、読まずに置いてある位置（冒頭）。
  - 読み捨てた項目と、その `seq`。窓口の値が変わるまで、その項目は書かない。
  - 大きすぎて書けなかった項目と、そのときの平文の SHA-256。手元の値が変わるまで、その項目は書かない。

サインアウトしたとき・鍵が替わったとき・窓口が `reset: true` を返したときは同期の記録を消し、「初めての同期」からやり直す。手元の設定と oplog は消さない。

## 1回の同期

1. **読む。** `GET /v1/sync` で `since` からの項目を、`more` が false になるまで取る。記録の `seq` 以下の項目は、もう見たものとして飛ばす。自分が書いた項目の読み戻しと、古い暗号文の出し直しを、新しい変更と取り違えないため。
2. **項目ごとに比べる。** oplog に載っていれば「手元を変えた」、載っていなければ「手元は変えていない」とする。並びは、記録の SHA-256 と比べる（「食い違い」）。
   - 手元は変えていない: 窓口の値を手元に入れる（消した記録なら手元からも消す）。
   - 手元を変えたが、窓口の値と同じ: 記録だけを揃える。
   - 手元を変えていて、窓口の値と違う: 後から変えた方を残す（「食い違い」）。
   - `detached` の印: 手元のその行の `sync` を false にし、記録から外す。
3. **書く。** 手元を変えた項目と、まだ窓口に書いていない項目を、`PUT /v1/sync` でまとめて書く（1回に 100 項目まで）。`base_seq` は記録の `seq`、初めての項目は `null`。
   - 同期していた行を消した: `deleted: true` を書く。
   - 同期していた行の `sync` を false にした: `detached` の印を書き、記録から外す。
   - 暗号文が窓口の1項目の上限（256 KiB）を超える項目は書かず、記録に置く。
   - `conflict` が返ったら、応答の `conflicts` にある今の項目を、読んだ項目と同じに扱って 2. からやり直す（3回まで）。初めての同期の途中なら、初めての同期の決まりで合わせる。
   - 100 項目を超えて何回かに分けて書くとき、途中で失敗しても、書けた回の項目は記録に置く。
4. **記録を置く。** 揃った項目の `seq` と SHA-256、次の `since` を書く。

通信の間に手元の設定が変わっていたら、読んだ値は手元に入れずに捨て、もう一度同期する。そのときも、窓口に書けた項目の `seq` と SHA-256 だけは記録に置く。書いたことを忘れると、次の回に自分の書き込みを他人の変更と取り違えるため。ただし並びの項目は、同期を始めたときの手元の並びと同じ値を書いたときだけ置く。届いた並びに手元の行を足して書いた並びは、手元には入っていないので、次の回に読み直して合わせ直す。

窓口の値を手元に入れるときは、画面から保存するときと同じ検査と、同じ反映（ホットキーの登録の付け替え・ウィンドウやトレイへの反映など）を通す。検査を通らない項目は読み捨てる。ホットキーとキー操作は互いに重なりを見るので、同じ回に届いた両方を入れた後の組で検査する。範囲のある値（履歴の件数・文字の大きさ）は、範囲の外なら収めずに読み捨てる（収めて入れると、届いた値と違う値を書き戻すため）。開いている設定の窓には、同期で設定が変わったことを知らせ、一覧を写し直させる。写し直さないと、次の編集で、届いた行を画面の古い並びで上書きして消すため。

## 初めての同期

記録が無いデバイスは、窓口の写し全体を読んでから、次のように合わせる。初めての同期の結果を手元に入れずに捨てたとき（通信の間に手元の設定が変わったとき）は、`since` が 0 の記録を置き、次の回も初めての同期として合わせる。そのとき、記録にある項目（自分が書いた項目）だけは、いつもの決まりで比べる。空の窓口へ初めて同期したデバイスも、読む位置が 0 のままなので、次の回は同じ扱いになる。

- 設定の項目: 窓口に項目があれば、窓口の値を手元に入れる。無ければ、手元の値を書く。
- 行: 窓口の行と手元の行を両方残す。窓口に無い手元の行のうち、中身が窓口の行と同じもの（`id` と `sync` を除いて一致）は、手元の行の `id` を窓口の `id` に替えて1つにする。窓口の行どうしは、中身が同じでも1つにしない。
- 窓口に消した記録がある `id` の行が手元にあれば、手元からも消す。同期から外した印がある `id` の行は、`sync` を false にする。
- 並び: 窓口の並びの後ろに、手元にだけある行を続ける。

## 食い違い

手元も窓口も変わっていて値が違う項目は、後から変えた方を残す（Wox・Chrome の同期と同じ）。止めて利用者に選ばせる形は採らない。食い違いはオフラインの2台で同じ項目を変えたときにしか起きず、消えた値は毎日のバックアップ（docs/config.md「バックアップ」）から戻せるため。

- 比べるのは、手元の oplog の時刻と、窓口の平文の `at`。手元の方が後なら、記録を窓口の今の `seq` に進めて、手元の値で上書きする。窓口の方が後か同じなら、窓口の値を手元に入れ、oplog から外す。同じ時刻で窓口を取るのは、どちらのデバイスも同じ側に揃って書き戻し合わないため。
- デバイスの時計がずれていると、ずれた分だけ後から変えたとみなされる。時計は OS が合わせるので、ずれは小さいものとして扱う。
- 片方で行を消し、もう片方でその行を変えたときは、変えた行を残して書き直す。消した側の時刻は窓口に残らず比べられないうえ、変えた行を消す方が取り返しが付かないため。
- 並び（`o_…`）は後勝ちにしない。窓口の並びの後ろに、手元にだけある行を続けて合わせる（初めての同期と同じ）。2台がそれぞれ行を足しただけで起きるため。

## 履歴の同期

テキストウィンドウの履歴は、collection `history` の1項目（`id` は `h`）に全体を置く。暗号・関連データ・平文の包み（`{ "v": 1, "value": … }`）は設定と同じ。同期が動く条件と、きっかけ（「いつ同期するか」）も設定と同じで、設定の同期と同じ回に読み書きする。履歴を覚えたとき・消したときも、設定を変えたときと同じく 3 秒後に同期する。

- 値: `{ "entries": [{ "text": <本文>, "at": <覚えた時刻。UNIX のミリ秒で、1 以上> }], "cleared_at": <履歴を消した時刻。消していなければ 0> }`。`entries` は古い順で、100 件まで。
- 手元の履歴ファイルにも、本文ごとの時刻と、消した時刻を置く。時刻が無いと、デバイスをまたいだ新しい順が決まらないため。
  - 時刻の無い前の形のファイルは、読むときに、ファイルの更新時刻から古い順に 1 ミリ秒ずつさかのぼった時刻を付ける（いちばん新しい本文が更新時刻。更新時刻が取れなければ今の時刻）。どれも同じ時刻にすると、デバイスをまたいだ順が決まらず、同じ本文が2回あるときに新しい方を残せないため。付けたら、その場で今の形で保存し直す。
  - 今の形のファイルに時刻が 0 の本文があれば、同じく、次に新しい本文の 1 ミリ秒前（いちばん新しい本文なら更新時刻）を付ける。
  - 履歴を消しても、消した時刻を置いたファイルは残す。履歴も消した時刻も無いときだけ、ファイルを置かない。
- 時刻は、画面から保存するときに付ける。画面は本文の一覧だけを持つので、前に保存した履歴の末尾と、届いた一覧の先頭が重なるいちばん長い所を、引き続きある本文とみて前の時刻を保ち、その後ろを新しく覚えた本文として今の時刻を付ける。
  - 前にも覚えた本文をもう一度覚えたときは、新しい方に今の時刻が付く。直前に覚えた本文と同じ本文は、画面が覚え直さないので、時刻も前のまま。
  - 新しく覚えた本文の時刻は、消した時刻と、引き続きある本文の時刻より後にする（同じ回に覚えた本文は 1 ミリ秒ずつずらす）。時計が戻っている・ほかのデバイスの時計が進んでいるときに、今覚えた本文が、消したはずの履歴として落ちたり、古い方へ入ったりしないため。

### 混ぜ方

履歴は食い違いにせず、聞かずに混ぜる。

1. `cleared_at` は、手元と窓口の大きい方にする。
2. 手元と窓口の `entries` を合わせ、`at` が `cleared_at` 以下のものを落とす。履歴を消したデバイスがあれば、それより前に覚えた履歴はどのデバイスからも消すため。入れないと、消した履歴が窓口から戻る。
3. 同じ本文は、`at` が大きい方の1つにする。
4. `at` の古い順に並べ、新しい方から 100 件を残す。`at` が同じ履歴は、本文の順に並べる。

混ぜた結果は、どちらが手元でどちらが窓口かに依らない。依ると、並びや 100 件で落とす履歴がデバイスごとに違い、書き戻し合って収まらないため。

- 混ぜた結果が手元と違えば手元に入れ、窓口の値と違えば書く。手元に入れるときは、そのデバイスの履歴の件数（`text_history_size`）に切り詰める。同じ回に件数の設定が届いたら、届いた後の件数にする。窓口に書く値は切り詰めない（件数の少ないデバイスが、ほかのデバイスの履歴を削らないため）。
- 履歴の件数が 0 のデバイスも、同じように同期する。手元に入れる履歴が 0 件になるだけ。
- 履歴を消したとき（件数を 0 にしたときを含む）は、消した時刻を手元に置く。次の同期で窓口とほかのデバイスの履歴も消える。件数は同期する設定なので、0 にしたデバイスが窓口の履歴を消さないと、どのデバイスも 0 になった後に窓口の履歴が残る。
  - 件数が 0 のままの起動では、消す履歴が手元にあるときだけ、消した時刻を置く。起動のたびに置くと、まだ件数が届いていないデバイスが覚えた履歴を消すため。
- そのデバイスで初めて履歴を同期する回（履歴の項目の記録が無い回。サインアウトや鍵の替わりで記録を消した後を含む）と、オフにしていた履歴の同期をオンに戻した回は、手元の消した時刻を使わず、窓口の消した時刻に替える（窓口に値が無ければ 0）。同期していなかった間に消したことで、ほかのデバイスの履歴まで消さないため。手元の履歴は消した後のものなので、消した履歴が手元から窓口へ戻ることはない（窓口に残っていれば、窓口からは戻る）。
- 記録の SHA-256 は、窓口の値でなく、揃ったときの手元の履歴（件数に切り詰めた後）と件数のものにする。件数の少ないデバイスの手元は窓口の値と違うので、窓口の値の SHA-256 では、手元を変えたかを見分けられないため。件数を含めるのは、件数を増やしたときに、窓口にある古い履歴を入れるため。
- 手元か件数を変えていて、窓口の値が届いていない回は、記録の `seq` の1つ前から1項目だけ読み直して、窓口の今の値と混ぜてから書く。手元は件数に切り詰めてあり、手元だけで書くと、ほかのデバイスの履歴を削るため。読み直しで記録の `seq` の項目が返らなければ、`base_seq` を `null` にして書き、`conflict` で返った今の値と混ぜる。
- 書いて `conflict` が返ったら、返った今の値ともう一度混ぜて書き直す（3回まで）。食い違いとして止めない。
- 届いた値を、その回に混ぜて揃えられなかった（書けなかった・手元の履歴を読めなかった）ときは、記録の `seq` だけを届いた値のものに進める。届いた値は次の回には届かないので、次の回に読み直して混ぜる。
- 暗号文が1項目の上限を超えるときは、古い方から落として収める。1件だけで上限を超える本文は、先に外す（外さないと、ほかの履歴を全部落としても収まらない）。落とす・外すのは窓口に書く値だけで、手元の履歴は削らない。
- 履歴の読み書きに失敗しても、同じ回の設定の同期の結果は捨てない。設定の結果を手元に入れずに捨てる回も、混ぜた履歴は手元に入れる。
- 通信の間に手元の履歴が変わっていたら、混ぜた結果で上書きせず、今の手元ともう一度混ぜてから入れ、もう一度同期する。
- 読めない値（復号できない・知らない `v`・形が合わない・時刻の無い履歴がある・100 件を超える）は読み捨て、窓口の値が変わるまで書かない（設定と同じ）。
- 開いているテキストウィンドウには、同期で履歴が変わったことを知らせ、履歴を読み直させる。履歴をたどっている途中なら、たどり終えてから入れ替える。テキストウィンドウが読み直す前の保存で、届いた履歴を上書きしない。

## いつ同期するか

- 起動して、Pro と鍵の確かめが済んだとき。
- 設定を変えた 3 秒後（続けて変えたら、最後の変更から数える）。打つたびに送らないため。
- 設定の窓を出したとき。
- テキストウィンドウを出したとき（前にこのきっかけで同期してから 10 秒たっていれば）。ほかのデバイスで覚えた履歴を、出してすぐたどれるようにするため。覚えた側が窓口へ書くのは 3 秒後なので、それより早く出すと、次に出したときに届く。
- 15 分おき。ほかのデバイスの変更を、設定の窓を開かなくても受け取るため。

同期は同時に1つだけ走らせる。走っている間に来たきっかけは、終わった後の1回にまとめる。

## 失敗したとき

- 窓口につながらない・一時的な失敗: 何もせず、次のきっかけで試す。
- `key_mismatch`: 鍵の状態を確かめ直す（「同期のパスワード」）。
- 413 の `limit`: 1項目の上限は書く前にアプリが測って外すので、返るのは全体か1回の要求の上限。そのまとまりを書くのをやめ、種類だけをログに残して、次のきっかけで試す。
- 失敗は利用者の操作を止めない。詳しくはログにだけ残す。
