# 設定と履歴の同期

Pro の Mawok は、同じアカウントのデバイスの間で、設定とテキストウィンドウの履歴を同期する。窓口（`docs/account-server.md`「同期」）には暗号文だけを置き、鍵はデバイスだけが持つ（`docs/lan.md`「アカウントの鍵」）。

同期が動くのは、Pro で、アカウントの鍵が `Ready` で、設定ファイルの `sync_enabled` が true のとき。

## 同期する単位

窓口の1項目は `collection` と `id` で見分ける。履歴は下の「履歴の同期」。設定の同期は、全部を collection `settings` に置き、`id` の頭の1文字で種類を分ける（窓口の `id` は英数字と `_`・`-` の 64 文字までで、collection は `settings` と `history` だけのため）。

| 種類 | 窓口の id | 中身 |
| --- | --- | --- |
| 設定の項目 | `s_<項目名>` | その項目の値 |
| 置き換え辞書の行 | `r_<行の id>` | その行（`id` と `sync` を除く） |
| 定型文の行 | `n_<行の id>` | 同上 |
| アクションの行 | `a_<行の id>` | 同上 |
| 並び | `o_replacements`・`o_snippets`・`o_actions` | 同期する行の `id` の並び |

設定の項目は次のとおり。

- どのデバイスでも同じ値にする項目: `language`・`theme`・`text_window_always_on_top`・`hide_text_window_on_blur`・`show_text_window_buttons`・`text_history_size`・`trim_trailing_whitespace`・`punctuation_style`・`char_widths`・`exclude_from_clipboard_history`・`text_font_size`・`text_color_light`・`text_color_dark`・`input_guidance`・`ai_service`・`ai_models`。
- OS ごとに分ける項目: `hotkey`・`text_window_keys`・`text_font_family`。id の後ろに `_macos` か `_windows` を付け（`s_hotkey_macos` など）、自分の OS の項目だけを読み書きする。キーの名前と入っている書体が OS で違うため。
- 同期しない項目: `autostart`・`devices`・`ai_consent`・`sync_enabled`・`yielded_draft_keys`。AI サービスのキー（OS の資格情報管理）、アカウントと Pro の状態、ウィンドウの位置も同期しない。デバイスに固有か、デバイスごとに本人が決めるものであるため。

行（置き換え辞書・定型文・アクション）は、`sync` が true の行だけを同期する。`sync` が false の行は、同じ `id` の項目が窓口から届いても、中身も `sync` も変えない。同期から外した行を、手元の項目として保つため。

- 設定ファイルに書いていない既定のアクションは同期しない（行も並びも書かない）。編集して設定ファイルに書かれたときから同期する。既定のアクションの `id` は、アクションごとに決まった値にする。2台で別々に編集しても、同じアクションが2つに増えないため。
- 既定のアクションのうち、コマンドの見本（`sort`）は `sync` を false にしておく。文字コードの既定が OS で違うため。
- 既定のアクションのままのデバイスにアクションの行か並びが届いたら、同期しない既定のアクションだけを設定に書き出し、同期する行は届いたものだけにする。届いた行を、書き出した既定の値と比べない。既定の値は表示言語で違うので、比べると手元を変えていないのに食い違いになるため。ほかのデバイスで消した既定のアクションを、戻さないためでもある。
- 既定で同期する既定のアクションを、同期しない行として初めて設定に書いたデバイスは、その `id` に同期から外した印を書く。窓口にその `id` の項目がすでにあれば印は書かず、手元の行を同期しないまま残す（ほかのデバイスが同期している行を外さないため）。印が届いた既定のアクションのままのデバイスは、印が届いた時点で既定のアクションを設定に書き出し、その既定のアクションを `sync` が false の行として残す。同じ回に届いた項目では、印を行と並びより先に入れる。印が無いと、窓口の上で「消した」と見分けられず、外しただけのアクションがほかのデバイスから消えるため。
- 並びは、並びの項目（`o_…`）で揃える。同期しない行は、手元で直前にある行の後ろに置いたままにする。届いた並びに、手元で同期する行として持っていない `id`（同期しない行・手元に無い行）があれば、それを除いた並びで揃ったとみなす。除かないと、その行を同期するデバイスと並びを書き戻し合うため。

## 暗号

- 鍵: アカウントの鍵から HKDF-SHA256（info は `mawok sync v1`）で導いた 32 バイト。
- 方式: XChaCha20-Poly1305。項目ごと・書くたびに 24 バイトの乱数の nonce を作る。
- 関連データ: `key_id`・`collection`・`id` を、それぞれ長さ（4 バイトのビッグエンディアン）を前に付けてつないだもの。別の項目の暗号文を差し替えられないため。
- 窓口に渡す `data`: nonce と暗号文をつないで base64 にしたもの。
- 平文: JSON の `{ "v": 1, "value": <値> }`。行を同期から外したことを伝えるときは `{ "v": 1, "detached": true }`。

復号できない項目と、知らない `v`・知らない項目名・形の合わない値は、読み捨てる（新しい版が書いた項目を、古い版が壊さないため）。読み捨てた項目は書き戻さない。

## 手元の記録

`sync-state.json`（`pro-state.json` と同じ場所）に次を置く。

- `key_id` と、次に読む位置（`since`）。
- 項目ごとに、最後に窓口と揃ったときの `seq` と、そのときの平文の SHA-256。
- 窓口で消えた・同期から外れた項目の `seq`。同じ id をもう一度書くときの `base_seq` に使う。
- 食い違いで止めている項目（下の「食い違い」）。
- 読み捨てた項目と、その `seq`。窓口の値が変わるまで、その項目は書かない。
- 大きすぎて書けなかった項目と、そのときの平文の SHA-256。手元の値が変わるまで、その項目は書かない。

サインアウトしたとき・鍵が替わったとき・窓口が `reset: true` を返したときは消し、「初めての同期」からやり直す。手元の設定は消さない。

## 1回の同期

1. **読む。** `GET /v1/sync` で `since` からの項目を、`more` が false になるまで取る。記録の `seq` 以下の項目は、もう見たものとして飛ばす。自分が書いた項目の読み戻しと、古い暗号文の出し直しを、新しい変更と取り違えないため。
2. **項目ごとに比べる。** 手元の今の値の平文の SHA-256 が、記録と同じなら「手元は変えていない」、違えば「手元を変えた」とする。
   - 手元は変えていない: 窓口の値を手元に入れる（消した記録なら手元からも消す）。
   - 手元を変えたが、窓口の値と同じ: 記録だけを揃える。
   - 手元を変えていて、窓口の値と違う: 食い違いとして止める。
   - `detached` の印: 手元のその行の `sync` を false にし、記録から外す。
3. **書く。** 手元を変えた項目（食い違いで止めているものを除く）を、`PUT /v1/sync` でまとめて書く（1回に 100 項目まで）。`base_seq` は記録の `seq`、初めての項目は `null`。
   - 同期していた行を消した: `deleted: true` を書く。
   - 同期していた行の `sync` を false にした: `detached` の印を書き、記録から外す。
   - 暗号文が窓口の1項目の上限（256 KiB）を超える項目は書かず、記録に置く。
   - `conflict` が返ったら、応答の `conflicts` にある今の項目を、読んだ項目と同じに扱って 2. からやり直す（3回まで）。初めての同期の途中なら、初めての同期の決まりで合わせる。
   - 100 項目を超えて何回かに分けて書くとき、途中で失敗しても、書けた回の項目は記録に置く。
4. **記録を置く。** 揃った項目の `seq` と SHA-256、次の `since` を書く。

通信の間に手元の設定が変わっていたら、読んだ値は手元に入れずに捨て、もう一度同期する。そのときも、窓口に書けた項目の `seq` と SHA-256 だけは記録に置く。書いたことを忘れると、次の回に自分の書き込みを他人の変更と取り違えるため。ただし並びの項目は、同期を始めたときの手元の並びと同じ値を書いたときだけ置く。届いた並びに手元の行を足して書いた並びは、手元には入っていないので、次の回に読み直して合わせ直す。

窓口の値を手元に入れるときは、画面から保存するときと同じ検査と、同じ反映（ホットキーの登録の付け替え・ウィンドウやトレイへの反映など）を通す。検査を通らない項目は読み捨てる。ホットキーとキー操作は互いに重なりを見るので、同じ回に届いた両方を入れた後の組で検査する。範囲のある値（履歴の件数・文字の大きさ）は、範囲の外なら収めずに読み捨てる（収めて入れると、届いた値と違う値を書き戻すため）。開いている設定の窓には、同期で設定が変わったことを知らせ、一覧を写し直させる。写し直さないと、次の編集で、届いた行を画面の古い並びで上書きして消すため。

## 初めての同期

記録が無いデバイスは、窓口の写し全体を読んでから、次のように合わせる。初めての同期の結果を手元に入れずに捨てたとき（通信の間に手元の設定が変わったとき）は、`since` が 0 の記録を置き、次の回も初めての同期として合わせる。そのとき、記録にある項目（自分が書いた項目）だけは、いつもの決まりで比べる。空の窓口へ初めて同期したデバイスも、読む位置が 0 のままなので、次の回は同じ扱いになる。

- 設定の項目: 窓口に項目があれば、窓口の値を手元に入れる。無ければ、手元の値を書く。
- 行: 窓口の行と手元の行を両方残す。窓口に無い手元の行のうち、中身が窓口の行と同じもの（`id` と `sync` を除いて一致）は、手元の行の `id` を窓口の `id` に替えて1つにする。窓口の行どうしは、中身が同じでも1つにしない。
- 窓口に消した記録がある `id` の行が手元にあれば、手元からも消す。同期から外した印がある `id` の行は、`sync` を false にする。
- 並び: 窓口の並びの後ろに、手元にだけある行を続ける。

## 食い違い

手元も窓口も変わっていて値が違う項目は、どちらも上書きせずに止め、記録に置く。止めている間、その項目は読みも書きもしない。どちらを残すかは利用者が選ぶ（選ぶ画面は別に作る）。

## 履歴の同期

テキストウィンドウの履歴は、collection `history` の1項目（`id` は `h`）に全体を置く。暗号・関連データ・平文の包み（`{ "v": 1, "value": … }`）は設定と同じ。同期が動く条件と、きっかけ（「いつ同期するか」）も設定と同じで、設定の同期と同じ回に読み書きする。履歴を覚えたとき・消したときも、設定を変えたときと同じく 3 秒後に同期する。

- 値: `{ "entries": [{ "text": <本文>, "at": <覚えた時刻。UNIX のミリ秒> }], "cleared_at": <履歴を消した時刻。消していなければ 0> }`。`entries` は古い順で、100 件まで。
- 手元の履歴ファイルにも、本文ごとの時刻と、消した時刻を置く。時刻が無いと、デバイスをまたいだ新しい順が決まらないため。時刻の無い前の形のファイルは、時刻を 0 として読む。

### 混ぜ方

履歴は食い違いにせず、聞かずに混ぜる。

1. `cleared_at` は、手元と窓口の大きい方にする。
2. 手元と窓口の `entries` を合わせ、`at` が `cleared_at` 以下のものを落とす。履歴を消したデバイスがあれば、それより前に覚えた履歴はどのデバイスからも消すため。入れないと、消した履歴が窓口から戻る。
3. 同じ本文は、`at` が大きい方の1つにする。
4. `at` の古い順に並べ、新しい方から 100 件を残す。

- 混ぜた結果が手元と違えば手元に入れ、窓口の値と違えば書く。手元に入れるときは、そのデバイスの履歴の件数（`text_history_size`）に切り詰める。窓口に書く値は切り詰めない（件数の少ないデバイスが、ほかのデバイスの履歴を削らないため）。
- 履歴の件数が 0 のデバイスは、履歴を読みも書きもしない。
- 履歴を消したとき（件数を 0 にしたときを含む）は、消した時刻を手元に置く。
- 書いて `conflict` が返ったら、返った今の値ともう一度混ぜて書き直す。食い違いとして止めない。
- 暗号文が1項目の上限を超えるときは、古い方から落として収める。
- 読めない値（復号できない・知らない `v`・形が合わない）は読み捨て、窓口の値が変わるまで書かない（設定と同じ）。
- 開いているテキストウィンドウには、同期で履歴が変わったことを知らせ、履歴を読み直させる。履歴をたどっている途中なら、たどり終えてから入れ替える。

## いつ同期するか

- 起動して、Pro と鍵の確かめが済んだとき。
- 設定を変えた 3 秒後（続けて変えたら、最後の変更から数える）。打つたびに送らないため。
- 設定の窓を出したとき。
- 15 分おき。ほかのデバイスの変更を、設定の窓を開かなくても受け取るため。

同期は同時に1つだけ走らせる。走っている間に来たきっかけは、終わった後の1回にまとめる。

## 失敗したとき

- 窓口につながらない・一時的な失敗: 何もせず、次のきっかけで試す。
- `key_mismatch`: 鍵の状態を確かめ直す（`docs/lan.md`「アカウントの鍵」）。
- 413 の `limit`: 1項目の上限は書く前にアプリが測って外すので、返るのは全体か1回の要求の上限。そのまとまりを書くのをやめ、種類だけをログに残して、次のきっかけで試す。
- 失敗は利用者の操作を止めない。詳しくはログにだけ残す。
