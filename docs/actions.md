# 宛先へ出す

テキストを、1行目の宛先（AI サービス・その機のシェル）へ出す機能の、宛先の読み方、コマンドの渡し方、AI への送り方。

## 宛先

`@` は宛先の印。チャット・メール・エディタの AI のチャット（`@` に続けて相手の名前を書く）と同じ読み方に揃える。

| 1行目 | 出す先 | 中身の扱い |
| --- | --- | --- |
| `@ai 指示文` | AI サービス | 結果でテキストを置き換える |
| `@sh コマンド` | その機のシェル（macOS はログインシェル、Windows は cmd） | 結果でテキストを置き換える |

- 宛先を読むのは1行目の行頭だけ。大文字と小文字は区別しない。宛先の直後は空白か行の終わりに限る（`@aix` は宛先ではない）。
- 宛先は `@ai` と `@sh` の2つだけにする。できることを増やすより、覚えることを少なく保つため。別のデバイスで続きを使うには、コピーして、別のデバイスで履歴を戻る（`docs/sync.md`「履歴の同期」）。
- 宛先の読み方は `src/lib/addressee.ts`（画面）と `src-tauri/src/actions.rs` に置く。

### テキストウィンドウに書いて出す

- 1行目が宛先、2行目から下が中身（標準入力・AI に渡す文）。ノートブックのセルマジック（1行目が指示、下が中身）と同じ形。
- 出すのは、コピーして隠すキー（既定は `CommandOrControl+Enter`）とそのボタン。1行目が宛先なら、コピーせずに実行し、ボタンは「実行」の表示になる。キーを1つにして、覚えることを減らすため。先頭の印で同じキーの動きが変わるのは、チャットの `/コマンド` と同じ。実行だけ・コピーだけのキーやボタンは置かない（宛先で始まる文をコピーするには、OS のコピーを使う）。
- 貼り付けた文・履歴から戻した文が宛先で始まっていても、キーを押すまで動かさない。
- 1行目が宛先でない文は、コピーして隠す。`@` で始まっていても、`@ai`・`@sh` でなければ同じ（チャット向けの `@tanaka …` は、ふつうの文）。
- 結果でテキスト全体（1行目も含む）を置き換え、文字コードは UTF-8。出した時点のテキストは、呼び戻して直せるよう履歴に1件として残す。
- 1行目の行頭の `@` の直後を打っている間、宛先の候補（`@ai`・`@sh`）を出す。打った字で絞り、`Tab` か `Enter` で入れ、`Esc` で閉じる。出すのは、テキストの先頭が `@` で、カーソルが1行目の行末にあるときだけ。本文の途中の `@`（メールアドレス・チャット向けの宛名）では出さない。変換中の文字は、確定するまで候補の元にしない。

### 定型文

- 定型文は、名前と本文を登録しておく文。本文が1行だけで宛先から始まる定型文は、一覧で選ぶと、一覧を出したときのテキスト（選んだ範囲、選んでいなければ全体）を中身にして出す。ほかの定型文は、カーソルの位置に挿入する。
  - 2行目から下に中身まで書いてある定型文は、宛先で始まっていても挿入する。そのまま出せる書きかけなので、挿入した後にコピーのキーで出す。
- `@ai`・`@sh` の定型文は、結果の出し方（置換・挿入・出さない）を持つ。`@sh` の定型文は、文字コード（下の「文字コード」）も持つ。
- 定型文は1件ずつ切れる。切った定型文は一覧に出さない。
- 定型文を変えていなければ、既定の定型文（AI に頼む「英訳」と、行を並べ替える `@sh sort`）を今の表示言語で出す。利用者が全部消したときは、空のままにする（docs/config.md）。

実行する文は、定型文を選んで出すときは、一覧を出したときに入力欄で範囲を選んでいればその範囲、選んでいなければ入力欄の中身全体。テキストウィンドウに書いて出すときは、2行目から下。

## AI（`@ai`）

- 行頭の `@ai` の後ろ（前後の空白を除く）を指示文にする。`@ai` は行頭にだけ効き、残りは全部が指示文として送られる。`| sort` のように書いても、シェルには渡らない（マニュアルに書く）。
- 指示文の後ろに実行する文を付けて送る。実行する文が空なら、指示文だけを送る。
- 定型文から出すときの結果の出し方（置換・挿入・出さない）は、`@sh` の定型文と同じく選べる。
- AI サービスが OpenAI のときは、Chat Completions（`<ベース URL>/chat/completions`）で送る。ベース URL を替えると、OpenAI と互換のサービス（DeepSeek・OpenRouter・Ollama など）に送れる。ベース URL はモデルと組で使うので、モデルと同じく同期する。了解は、了解したときのベース URL と組で記録し（`ai_consent_base_url`。了解と同じく同期しない）、今のベース URL と違えば了解していないものとして取り直す。同期やバックアップから戻したことで替わったときも同じ。キーもベース URL ごとに分けて資格情報管理に置く。分けないと、OpenAI のキーを入れたまま送り先を替えたときに、OpenAI のキーを別のサービスへ送ってしまうため。

## コマンド

- コマンドは、`@sh` の後ろに、シェルを通す1行で書く。ターミナルで試した1行（パイプやリダイレクトを含む）をそのまま貼れるようにするため。
  - macOS は、ログインシェル（環境変数 `SHELL` のシェル。無ければ `/bin/zsh`）に `-l -c` で渡す。Dock などから起動した GUI のアプリは、ターミナルの PATH を引き継がないので、ログインシェルで読む設定の PATH で動かす。`~/.zshrc` にだけ書いた PATH は読まれないので、見つからないときはフルパスで書くよう、マニュアル（使い方と「うまくいかないとき」）に書く。
  - Windows は `cmd.exe /d /v:off /s /c "<コマンド>"` で渡す（Windows の実機で比べた）。cmd は標準入出力を読まずに子へ引き継ぐので、テキストのバイトがそのまま届く。PowerShell はパイプやコマンドレットでテキストが化け、起動も 6〜10 倍遅い。`/d` は、レジストリの AutoRun を走らせないため。`/v:off` は、遅延展開を切るため（何も付けないとレジストリの既定に従う）。遅延展開が効くと、`!` を含む行で `^` が消え、`!VAR!` が展開されて、`node -e "…!s…/^/…"` のような行が壊れる。PowerShell で書きたい人は `pwsh -NoProfile -Command "…"` を1行に書けば、cmd の下から呼べる。
- 実行する文は、標準入力だけで渡す。渡し方を1つにして分かりやすくするため。引数で受け取るコマンドへは、macOS なら `"$(cat)"` のように、シェルの側で標準入力を引数にできる。
- 渡すもの:
  - 標準入力: 実行する文の前の空行と後ろの空白と改行を除き、末尾に改行を1つ足して定型文の文字コード（下の「文字コード」）で書き込み、書き終えたら閉じる。除いた後が空なら、何も書かずに閉じる。1行目の字下げは除かない。行ごとに加工するコマンドで、1行目だけ崩れないため。改行を足すのは、行を数えるコマンド（`wc -l` など）が最後の行も数えるようにするため。除いた前後は、差し替えるときに結果の前後に戻す。AI には前後の空白をすべて除いて渡し（1行目の字下げも除く。AI は結果の前後の空白を落とすので、除いておいて戻す）、同じく前後に戻す。
  - 作業フォルダー: テキストウィンドウで移ったフォルダー。移っていなければホームフォルダー（下の「作業フォルダー」）。
  - 環境変数: Mawok のものをそのまま渡す。Windows だけ、`PYTHONUTF8` が無ければ `1` を足す。Python は既定だと標準入出力を cp932 で扱い、テキストが化けるため。
- 文字コード: 標準入力へ書く文と、標準出力を読むときの文字コードを、`@sh` の定型文ごとに選ぶ。UTF-8（既定）・Shift_JIS・EUC-JP・JIS（ISO-2022-JP）・UTF-16 LE から選ぶ。
  - Windows に初めから入っているコマンド（`sort`・`findstr` など）は、UTF-8 ではなくシステムの文字コード（日本語なら Shift_JIS）で読み書きし、`chcp 65001` でも変わらない。今どきのコマンド（node・Python・git など）は UTF-8 で読み書きする。1行の先でどちらがテキストを読むかを Mawok は見分けられない（パイプでつないだ行もある）ので、利用者が選ぶ。サクラエディタの外部コマンド実行や EmEditor の外部ツールと同じ作法。
  - 両方の OS で選べる。macOS でも、Shift_JIS のスクリプトや変換のコマンドにつなぐときに使う。
  - 実行する文に、選んだ文字コードで表せない文字（Shift_JIS に絵文字や ¥ など）があれば、実行せずに失敗の帯で知らせる。置き換えて渡すと、化けた結果でテキストが置き換わり、終了コード 0 では気づけないため。書き出した文を同じ文字コードで読み戻し、元の文と違えば断る（変換の部品が、¥ を `\` に、ISO-2022-JP の半角カナを全角カナに、黙って書き出すため）。
  - Shift_JIS・EUC-JP・JIS では、JIS と Windows（cp932）で Unicode の対応づけが分かれる7字（〜‖−—¢£¬）を、Windows の側の字（～∥－―￠￡￢）に写して渡す。いわゆる波ダッシュ問題で、macOS や Web から来た文には JIS の側の字が多く、断ると日本語の文がよく止まるため。Windows の変換と同じ扱いで、結果には写した字が残る。
  - テキストウィンドウに書いて出した行は UTF-8 で実行する。
- 了解の画面は置かない。テキストを受け取るのは利用者が書いたコマンドで、その先を Mawok は知らない。マニュアルに、テキストは標準入力に渡されること、コマンドが外のサービスへ送るならそのサービスの規約と扱いに従い、それは利用者が確かめることを書く。
- 設定の説明や既定の設定に、特定の CLI の名前を例として出さない。Mawok は、つなぐ先が何であるかを知らない。OS に入っているコマンド（既定の定型文の `sort` など）は、つなぐ先ではないので当たらない。
- 標準入力を読まずに終わるコマンドもある（`ls` など）。書き込みが途中で断られても、失敗にしない。
- 結果の扱い（結果の出し方が「出さない」のときは、終了コードが 0 なら、標準出力が空でも読めなくても成功とし、標準出力は読み捨てる。ほかは次のとおり）:
  - 終了コードが 0 なら、標準出力を結果にする。改行は `\n` に揃え（Windows のコマンドの多くは `\r\n` で返す）、末尾の改行は落とす。コマンドが最後に付ける改行をテキストに残さないため（シェルの `$(...)` と同じ）。
  - 標準出力が空ならテキストを変えず、「何も返りませんでした」と失敗として知らせる。空で置き換えると、テキストが消えたように見えるため。結果を返さないコマンドには、出し方を「出さない」にしてもらう。
  - 終了コードが 0 以外ならテキストを変えず、失敗の帯に終了コードと、標準エラーの末尾の数行を出す。macOS で、シェルがコマンドを見つけられなかったとき（127）は、見つからなかったことを出す（直し方はマニュアルの「うまくいかないとき」）。Windows は見分けない。`cmd /c` は見つからなくても 1 で終わり（9009 は cmd の中の errorlevel にしか出ない）、拾うために後ろに `exit` などを足すと、`for` の `do` の後ろに入り込むなど、利用者の1行の意味を変えてしまうため（2026-09-26 に Windows の実機で確かめた）。見つからないことは、帯に出る cmd の標準エラーで分かる。Windows の標準エラーは、UTF-8 として読めなければコンソールのコードページ（日本語なら cp932）として読む。cmd のエラーはそちらで来るため。文字コードが UTF-8 の定型文では、標準出力も同じく読む。cmd の組み込みコマンド（`echo` など）の出力はコンソールのコードページで来て、`chcp 65001` でも変わらない。cp932 の日本語の文が、たまたま UTF-8 として読めることはまず無い。1バイト文字のコードページ（437・1252 など）では、どんなバイト列もそのコードページの文字として読めるので、下の「読めない」にはならない。
  - 標準出力が定型文の文字コードとして読めないとき（UTF-8 のときは、Windows はコンソールのコードページとしても読めないとき）、または 1 MB を超えたときは、止めて失敗にする。読めないときの失敗の帯では、設定で文字コードを確かめるよう促す。止まらずに出力し続けるコマンドへの備え。
  - 標準エラーはログに書かない。コマンドによっては秘密を含みうるため。
- 時間切れは置かない。止めるのは利用者が取り消したときだけ。
- 取り消したら、コマンドを子プロセスごと止める（macOS はプロセスグループ、Windows はジョブオブジェクト）。

## 作業フォルダー

コマンドを動かすフォルダーを、テキストウィンドウで移れる（`src-tauri/src/folder.rs`）。下書きの欄をターミナルのように使い、移ったフォルダーで続けてコマンドを動かすため。行の頭に `cd` を書く方法もあるが、行ごとに書くことになる。

- キー（既定は `CommandOrControl+KeyD`）で欄を出し、今のフォルダーを入れた状態から打ち直す。空ならホーム、`~` で始まればホームから、相対パスなら今のフォルダーから見る。
- `Tab` で、打ちかけの最後の名前をフォルダーの名前で補う（ターミナルの補完と同じ）。大文字と小文字は打ち分けなくてよいよう区別せずに拾い、補った所は実際の名前の書き方にする（区別するファイルシステムでも移れるように）。1つなら区切りまで、複数なら共通する所まで補い、候補を欄の下に並べる。隠したフォルダー（`.` で始まる名前と、Windows の隠しの属性）は、`.` を打ったときか、ほかに当てはまるものが無いときだけ候補にする。設定のフォルダーが、候補を埋めないため。Windows の隠しとシステムの両方の属性のフォルダー（`$Recycle.Bin`・`Application Data` など）は候補にしない。エクスプローラーも既定で出さず、移っても使えないものが多いため。
- 補い方はシェルに合わせる。利用者がターミナルで慣れた操作のまま使えるため。
  - 候補が並んだら、もう一度 `Tab`（戻るのは `Shift+Tab`、`↑`・`↓` も）で順に選んで欄に入れる（zsh の menu-select）。`Enter` は選んだ候補で決めるだけで移らず、続けてその中を補える。`Esc` は、選んでいれば選ぶ前の中身に戻し、候補が並んでいるだけなら一覧を閉じる（打ったパスを残す）。選んだまま打てば、その候補に続けて打てる。
  - 打っている間、1つに決まる続きを欄の中に薄く出し、`→` か `Tab` で受け入れる（fish の autosuggestion）。カーソルが末尾に無いときと、欄からはみ出しているときは出さない。重ねて出す続きの位置が、打った文字とずれるため。変換中の文字は、確定するまで続きの元にしない。
- マウスで使う人の入口として、左下に今のフォルダーの名前を出すボタンを置く（VS Code の下のバーと同じ作り）。押すと、最近移ったフォルダー（5件。起動し直しても残す。`app_local_data_dir` の `recent-folders.json`）・「フォルダーを選ぶ...」・「ホームフォルダーに戻る」のメニューを開く。最近のフォルダーが無くホームにいるときは、メニューを出さずにすぐ選ぶ画面を開く。最近のフォルダーは、まだあるかを確かめずに並べ、選んで移れなかったら理由を出し、フォルダーそのものが消えていたら（親はあるとき）一覧から外す。外付けのドライブを抜いた・ネットワークの共有がつながっていないだけのときは残す。つながらないネットワークのフォルダーがあると、確かめ終わるまでボタンが出ないため。キーの欄とは別の入口にする。キーで使う人とマウスで使う人の操作を混ぜると、どちらにも一手多くなるため。
- 「フォルダーを選ぶ...」は、OS のフォルダーを選ぶ画面を今のフォルダーから開く。選んだフォルダーは、打ったパスと同じく確かめてから移る。画面を出している間は、ほかのアプリに移ったら隠す設定でも下書きを隠さず、閉じたら下書きにフォーカスを戻す（`pick_folder`）。
- 移った先はテキストウィンドウのタイトルバーに出す。タイトルバーは設定や履歴にかかわらずいつも見え、入力欄を狭めないため。ホームならアプリの名前だけにする。macOS はホームの中を `~` で縮め、Windows は `~` を使わないのでそのまま出す。
- 今のフォルダーは起動している間だけ覚え、起動し直すとホームに戻る。設定には書かない。思っていない場所で動き出さないため。最近移ったフォルダーの一覧は、メニューに出すため保存する（下）。
- `@sh` の定型文と、テキストウィンドウに書いて出した `@sh` の行の両方に効く。`@ai` には関わらない。
- 移った後にフォルダーが消えていたら、ホームで動かさずに断る（`action.folder_missing`）。思っていない場所で動くと、相対パスのコマンドが別のファイルに触れるため。消えたフォルダーからの相対パスは、ホームから見る。
- `..` は文字の上で解き、シンボリックリンクは解かない（ターミナルの `cd` と同じ）。解くと、ドライブ文字を割り当てたネットワークのフォルダーが `\\server\share` の形になる。Windows の cmd はその形を作業フォルダーにできず、黙って `C:\Windows` で動くので、`\\` で始まるパスは断る。エクスプローラーの「パスのコピー」が付ける前後の `"` は外す。
- フォルダーの名前はログに書かない。
