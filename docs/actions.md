# アクションの実行

アクション（テキストをコマンドや AI サービスに通して差し替える機能）の、コマンドの渡し方と AI への送り方。

実行する文は、アクションの一覧を出したときに入力欄で範囲を選んでいればその範囲、選んでいなければ入力欄の中身全体。

## AI（`@ai`）

- 行頭の `@ai` の後ろ（前後の空白を除く）を指示文にする。`@ai` は行頭にだけ効き、残りは全部が指示文として送られる。`| sort` のように書いても、シェルには渡らない（マニュアルに書く）。
- 指示文に `{{t}}` があれば、実行する文にそのまま置き換えて送る（AI には引用符で囲まない）。無ければ、指示文の後ろに実行する文を付けて送る。実行する文が空なら、指示文だけを送る。
- 結果の出し方（置き換える・差し込む・出さない）は、コマンドのアクションと同じく選べる。

## コマンド

- コマンドは、シェルを通す1行で書く。ターミナルで試した1行（パイプやリダイレクトを含む）をそのまま貼れるようにするため。
  - macOS は、ログインシェル（環境変数 `SHELL` のシェル。無ければ `/bin/zsh`）に `-l -c` で渡す。Dock などから起動した GUI のアプリは、ターミナルの PATH を引き継がないので、ログインシェルで読む設定の PATH で動かす。`~/.zshrc` にだけ書いた PATH は読まれないので、見つからないときはフルパスで書くよう、マニュアルと、見つからなかったときの失敗の帯に書く。
  - Windows は `cmd.exe /d /s /c "<コマンド>"` で渡す（Windows の実機で比べた）。cmd は標準入出力を読まずに子へ引き継ぐので、テキストのバイトがそのまま届く。PowerShell はパイプやコマンドレットでテキストが化け、起動も 6〜10 倍遅い。`/d` は、レジストリの AutoRun を走らせないため。PowerShell で書きたい人は `pwsh -NoProfile -Command "…"` を1行に書けば、cmd の下から呼べる。
- 行の中の `{{t}}` は、実行する文（標準入力と同じく前後を除いたもの。改行は足さない）を1つの引数として埋め込む。中の空白・引用符・改行・記号は、コマンドとして解釈させない。テキストは文章なので、`'` や `;` がコマンドとして読まれると事故になるため。シェルの行そのものをテキストから打ちたいときは、`sh -c {{t}}` のようなアクションで明示的にする。`{{t}}` はいくつ書いてもよく、1つもなくてもよい。
  - macOS は、実行する文を単引用符で囲み（中の `'` は `'\''` に置き換える）、その場に埋め込む。
  - Windows は、`cmd` に任意の文字列を確実に囲う方法が無い（引用符の中でも `%VAR%` が展開され、`"` で囲いが外れる）ので、`{{t}}` を環境変数の遅延展開（`"!MAWOK_TEXT_QUOTED!"`）に書き換え、`cmd /d /v:on /s /c` で実行する。遅延展開は行を解釈した後に起きるので、中の記号がコマンドとして読まれない。代わりに、`{{t}}` のある行では、行の中の `!` が特別な意味を持ち、`^` が引用符の中でも消える（行に必ず `!` が入るため。マニュアルに書き、設定ではその行の欄の下にも出す）。受け取るプログラムは、引用符と `\` の規則（CommandLineToArgvW と C ランタイムの規則）で引数を分け直すので、展開するのは、その規則で囲い直した文を入れた `MAWOK_TEXT_QUOTED`（`"` の前に `\` を置き、`"` と文末の前の `\` の並びを倍にしたもの）にする。そのまま展開すると、`"` を含む文や `\` で終わる文が、複数の引数に割れたり、後ろの引数とつながったりするため。この規則に従わないプログラム（cmd の組み込みコマンドの `echo` など）には、囲い直した形のまま届く。`{{t}}` の無い行は `/v:off` で実行する（`cmd /d /v:off /s /c`。何も付けないとレジストリの既定に従うため、はっきり切る）。遅延展開が効くと、`!` を含む行で `^` が消え、`!VAR!` が展開されて、`node -e "…!s…/^/…"` のような行が壊れるため。行の上限は、`{{t}}` を展開した後の行で 8,191 字として断る（実機で、展開した後の行は 8,191 字を少し超えたところで失敗し、値が 8,192 字以上だと黙って空に展開されると確かめた）。実行する文が空なら、`{{t}}` は `""` にする。空の環境変数は無いものとして扱われ、`!MAWOK_TEXT_QUOTED!` が文字どおり残るため。
- 渡すもの:
  - 標準入力（`{{t}}` があってもなくても渡す）: 実行する文の前の空行と後ろの空白と改行を除き、末尾に改行を1つ足してアクションの文字コード（下の「文字コード」）で書き込み、書き終えたら閉じる。除いた後が空なら、何も書かずに閉じる。1行目の字下げは除かない。行ごとに加工するコマンドで、1行目だけ崩れないため。改行を足すのは、行を数えるコマンド（`wc -l` など）が最後の行も数えるようにするため。除いた前後は、差し替えるときに結果の前後に戻す。AI には前後の空白をすべて除いて渡し（1行目の字下げも除く。AI は結果の前後の空白を落とすので、除いておいて戻す）、同じく前後に戻す。
  - 作業フォルダー: テキストウィンドウで移ったフォルダー。移っていなければホームフォルダー（下の「作業フォルダー」）。
  - 環境変数: Mawok のものをそのまま渡し、`MAWOK_TEXT` に実行する文（標準入力と同じく前後を除いたもの。改行は足さない）を入れる。実行する文が大きすぎるとき（macOS は 256 KiB、Windows は環境変数の上限の 32,767 文字を超えるとき）や NUL を含むときは、環境変数にも引数にもできないので、`MAWOK_TEXT` を入れずに標準入力だけで渡す。行に `{{t}}` があり、埋め込めないときは実行せず、標準入力で受け取るコマンドにするよう失敗の帯で知らせる。埋め込めるかは組み上がる長さで見る（macOS は、埋め込んだシェルの行と `MAWOK_TEXT` を合わせて 768 KiB まで。ARG_MAX の 1 MiB に、ほかの環境変数の分の余裕を見る。Windows は、展開した後の cmd の行が 8,191 文字まで）。スクリプトの中からテキストを読む手段にもなる。Windows だけ、`PYTHONUTF8` が無ければ `1` を足す。Python は既定だと標準入出力を cp932 で扱い、テキストが化けるため。
- 文字コード: 標準入力へ書く文と、標準出力を読むときの文字コードを、アクションごとに選ぶ。UTF-8（既定）・Shift_JIS・EUC-JP・JIS（ISO-2022-JP）・UTF-16 LE から選ぶ。
  - Windows に初めから入っているコマンド（`sort`・`findstr` など）は、UTF-8 ではなくシステムの文字コード（日本語なら Shift_JIS）で読み書きし、`chcp 65001` でも変わらない。今どきのコマンド（node・Python・git など）は UTF-8 で読み書きする。1行の先でどちらがテキストを読むかを Mawok は見分けられない（パイプでつないだ行もある）ので、利用者が選ぶ。サクラエディタの外部コマンド実行や EmEditor の外部ツールと同じ作法。
  - 両方の OS で選べる。macOS でも、Shift_JIS のスクリプトや変換のコマンドにつなぐときに使う。
  - `{{t}}` と `MAWOK_TEXT` には関わらない。引数と環境変数は OS の文字列として渡すため。
  - 実行する文に、選んだ文字コードで表せない文字（Shift_JIS に絵文字や ¥ など）があれば、実行せずに失敗の帯で知らせる。置き換えて渡すと、化けた結果でテキストが置き換わり、終了コード 0 では気づけないため。書き出した文を同じ文字コードで読み戻し、元の文と違えば断る（変換の部品が、¥ を `\` に、ISO-2022-JP の半角カナを全角カナに、黙って書き出すため）。
  - Shift_JIS・EUC-JP・JIS では、JIS と Windows（cp932）で Unicode の対応づけが分かれる7字（〜‖−—¢£¬）を、Windows の側の字（～∥－―￠￡￢）に写して渡す。いわゆる波ダッシュ問題で、macOS や Web から来た文には JIS の側の字が多く、断ると日本語の文がよく止まるため。Windows の変換と同じ扱いで、結果には写した字が残る。
  - 一覧で打った行（「この内容で実行」）は UTF-8 で実行する。
- 了解の画面は置かない。テキストを受け取るのは利用者が書いたコマンドで、その先を Mawok は知らない。マニュアルに、テキストは標準入力に渡されること、コマンドが外のサービスへ送るならそのサービスの規約と扱いに従い、それは利用者が確かめることを書く。
- 設定の説明や既定の設定に、特定の CLI の名前を例として出さない。Mawok は、つなぐ先が何であるかを知らない。OS に入っているコマンド（既定のアクションの `sort` など）は、つなぐ先ではないので当たらない。
- 標準入力を読まずに終わるコマンドもある（`ls` など）。書き込みが途中で断られても、失敗にしない。
- 結果の扱い（結果の出し方が「出さない」のときは、終了コードが 0 なら、標準出力が空でも読めなくても成功とし、標準出力は読み捨てる。ほかは次のとおり）:
  - 終了コードが 0 なら、標準出力を結果にする。改行は `\n` に揃え（Windows のコマンドの多くは `\r\n` で返す）、末尾の改行は落とす。コマンドが最後に付ける改行をテキストに残さないため（シェルの `$(...)` と同じ）。
  - 標準出力が空ならテキストを変えず、「何も返りませんでした」と失敗として知らせる。空で置き換えると、テキストが消えたように見えるため。結果を返さないコマンドには、出し方を「出さない」にしてもらう。
  - 終了コードが 0 以外ならテキストを変えず、失敗の帯に終了コードと、標準エラーの末尾の数行を出す。macOS で、シェルがコマンドを見つけられなかったとき（127）は、フルパスで書くよう促す。Windows は見分けない。`cmd /c` は見つからなくても 1 で終わり（9009 は cmd の中の errorlevel にしか出ない）、拾うために後ろに `exit` などを足すと、`for` の `do` の後ろに入り込むなど、利用者の1行の意味を変えてしまうため（2026-09-26 に Windows の実機で確かめた）。見つからないことは、帯に出る cmd の標準エラーで分かる。Windows の標準エラーは、UTF-8 として読めなければコンソールのコードページ（日本語なら cp932）として読む。cmd のエラーはそちらで来るため。文字コードが UTF-8 のアクションでは、標準出力も同じく読む。cmd の組み込みコマンド（`echo` など）の出力はコンソールのコードページで来て、`chcp 65001` でも変わらない。cp932 の日本語の文が、たまたま UTF-8 として読めることはまず無い。1バイト文字のコードページ（437・1252 など）では、どんなバイト列もそのコードページの文字として読めるので、下の「読めない」にはならない。
  - 標準出力がアクションの文字コードとして読めないとき（UTF-8 のときは、Windows はコンソールのコードページとしても読めないとき）、または 1 MB を超えたときは、止めて失敗にする。読めないときの失敗の帯では、設定で文字コードを確かめるよう促す。止まらずに出力し続けるコマンドへの備え。
  - 標準エラーはログに書かない。コマンドによっては秘密を含みうるため。
- 時間切れは置かない。止めるのは利用者が取り消したときだけ。
- 取り消したら、コマンドを子プロセスごと止める（macOS はプロセスグループ、Windows はジョブオブジェクト）。

## 作業フォルダー

コマンドを動かすフォルダーを、テキストウィンドウで移れる（`src-tauri/src/folder.rs`）。下書きの欄をターミナルのように使い、移ったフォルダーで続けてアクションを動かすため。行の頭に `cd` を書く方法もあるが、アクションごとに書くことになる。

- キー（既定は `CommandOrControl+KeyD`）で欄を出し、今のフォルダーを入れた状態から打ち直す。空ならホーム、`~` で始まればホームから、相対パスなら今のフォルダーから見る。
- `Tab` で、打ちかけの最後の名前をフォルダーの名前で補う（ターミナルの補完と同じ）。大文字と小文字は打ち分けなくてよいよう区別せずに拾い、補った所は実際の名前の書き方にする（区別するファイルシステムでも移れるように）。1つなら区切りまで、複数なら共通する所まで補い、候補を欄の下に並べる。隠したフォルダー（`.` で始まる名前と、Windows の隠し・システムの属性）は、`.` を打ったときか、ほかに当てはまるものが無いときだけ候補にする。設定やシステムのフォルダーが、候補を埋めないため。
- 移った先はテキストウィンドウのタイトルバーに出す。タイトルバーは設定や履歴にかかわらずいつも見え、入力欄を狭めないため。ホームならアプリの名前だけにする。macOS はホームの中を `~` で縮め、Windows は `~` を使わないのでそのまま出す。
- 移った先は起動している間だけ覚える。設定ファイルには書かない。
- 登録したアクションと、一覧で打った行の両方に効く。AI のアクションには関わらない。
- 移った後にフォルダーが消えていたら、ホームで動かさずに断る（`action.folder_missing`）。思っていない場所で動くと、相対パスのコマンドが別のファイルに触れるため。消えたフォルダーからの相対パスは、ホームから見る。
- `..` は文字の上で解き、シンボリックリンクは解かない（ターミナルの `cd` と同じ）。解くと、ドライブ文字を割り当てたネットワークのフォルダーが `\\server\share` の形になる。Windows の cmd はその形を作業フォルダーにできず、黙って `C:\Windows` で動くので、`\\` で始まるパスは断る。エクスプローラーの「パスのコピー」が付ける前後の `"` は外す。
- フォルダーの名前はログに書かない。
