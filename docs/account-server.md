# 窓口（mawok.amiiby.com）

キーを持たない人も AI アクションを使えるよう、作者のキーで AI に中継し、使った分を前払いのクレジット（コードと以下では残高と呼ぶ）から引くサーバー（窓口）。アカウント・購入・中継を受け持つ。

## 作り

- `account-server/` に置く。Cloudflare Workers・Hono・D1・Resend・Stripe で作る。Stripe と Google は SDK を使わず fetch で呼ぶ。
- 本番は `mawok.amiiby.com`、確かめる環境は workers.dev に別の D1 で出す（`env.staging`）。紹介・規約類（`site/`）も同じ Worker の静的アセットで出し、`/account` と `/v1/` だけを Worker が受ける。
- 売るのは使えば減る残高で、毎回サーバーに問い合わせるので、オフラインで確かめる証明は持たない。

この文書とコードの語は、画面（Mawok・窓口・メール・規約類）では次のように呼ぶ。利用者に仕組みの語を見せないため。

| この文書                       | 画面                                             |
| ------------------------------ | ------------------------------------------------ |
| Mawok とアカウントを結ぶ・外す | （PC を）登録・登録を解除（英語は link・unlink） |
| 結んでいる Mawok               | 登録している PC                                  |
| 窓口                           | Mawok のアカウント（のページ・サービス）         |

## サインイン

- メールのリンク・Google・Apple。
- 外部のサインインで受け取ったメールが確かめ済みのときだけ、同じメールのアカウントに結ぶ。
- Apple:
  - 戻りは Apple のサイトからの POST（`form_post`）。往復の印の Cookie は `SameSite=None` にし、戻り先だけは送り元（Origin）を確かめず、state の照らし合わせで守る（ほかの書き込みは Origin の確かめのまま）。言語の Cookie はこの POST に付かないので、言語も往復の印に持つ。そのため https でしか通らず、手元では試せない。確かめる環境（`env.staging`）で試す。
  - 「メールを非公開」を選んだ人は、Apple の転送用アドレス（`@privaterelay.appleid.com`、2026 年の後半からの新しいアドレスは `@private.icloud.com`）のアカウントになる。転送用アドレスには登録した送り元のメールしか届かないので、Stripe の Checkout にはメールを渡さず、支払いの画面で入れてもらう。

## Mawok とアカウントを結ぶ

ブラウザを、Mawok が 127.0.0.1 で待ち受けているところへ戻して結ぶ（RFC 8252 のループバック）。戻り先が押した人の PC なので、他人から届いたリンクで押しても、リンクを作った人の Mawok には届かない。確認コードを見比べる手順は要らない。

1. 設定の「アクション」で「サインイン」を押すと、Mawok は 127.0.0.1 の OS が選んだポートで待ち受け、検証用の値（`verifier`、32 バイトの乱数の16進）と `state` を作る。
2. Mawok がブラウザで `/account/link?port=…&state=…&challenge=…&name=…` を開く。`challenge` は `verifier` の SHA-256 の16進、`name` はコンピューター名（窓口の一覧で見分けるため）。
3. 利用者はブラウザでサインインし、「この PC を登録」を押す。メールのリンクでサインインするときは、メールを送った画面で、リンクを同じパソコンで開くよう案内する（ほかの機器で開くと、その機器の 127.0.0.1 へ戻ってしまう）。窓口は一度きりのコード（5分）を作り、ブラウザを `http://127.0.0.1:<port>/callback?code=…&state=…` へ戻す。
4. Mawok は `state` を照らしてから、`POST /v1/links/token` でコードと `verifier` をトークンに替え、ブラウザに結果のページを返す。窓口はコードを照らす前に消し、`verifier` の SHA-256 が `challenge` と合うときだけトークンを渡す。待ち受けを他のプロセスに取られても、`verifier` が無いのでトークンに替えられない（RFC 7636 の PKCE と同じ考え方。窓口と Mawok の間だけの取り決めなので、`challenge` は base64url でなく16進にしている）。
5. トークンは 32 バイトの乱数で、窓口はハッシュだけを持つ。Mawok は OS の資格情報管理に置く（API キーと同じ置き場、`mawok-account-token`）。期限は持たず、Mawok でのサインアウトと、窓口のアカウントの画面（結んだ Mawok の一覧）から失効させる。

- 待ち受けるのは 127.0.0.1 だけ。ほかのアドレスで待ち受けると OS がファイアウォールの許可を求めるが、ループバックでは求めない（Windows の EXE 版・MSIX 版、macOS のアプリケーションファイアウォールで確かめた）。MSIX 版は full trust で動くので、UWP のループバックの制限は当たらない。
- 公開の https のページから `http://127.0.0.1` へのページそのものの移動は、Chrome・Edge の Local Network Access の制限の対象外（制限するのは fetch・iframe など）。
- 独自の URL スキーム（`mawok://`）は採らない。登録を配る形ごと（EXE・MSIX・macOS）に作ることになり、ブラウザがアプリを開いてよいかを毎回聞くため。
- 待つのは30分（メールのリンクの期限は送ってから15分なので、送るまでの分を足す）。設定の画面を閉じても待ち続け、開き直すとサインインの途中であることを出し直す。

## 中継

- `POST /v1/ai`（`Authorization: Bearer <トークン>`）で、Mawok が組み立てた指示文と文を受け、Gemini（`gemini-3.5-flash-lite`、有料枠）へ送って結果を返す。
- モデル・出力の上限・入力の上限は窓口で決め打ちし、Mawok からは変えさせない。Mawok の `@ai` に使う分だけを受け、生の API の代わりにさせないため（Google APIs Terms 4.a）。
- 送った文も結果も窓口のログや D1 に残さない。残すのは、日時・アカウント・トークン数・原価だけ。
- 同じアカウントは同時に 1 件だけ。Mawok で取り消して接続が切れても、Gemini の返事を待って使った分を引き、同時に 1 件の印を外すまで続ける（Workers の `waitUntil`）。

## 残高

- 単位は原価の 1/1000 円（milli_yen）の整数。原価は Gemini が返すトークン数（思考を含む出力）× 単価 × 円の換算で、切り上げる。単価と換算は「値付けの値」に持つ。
- 残高は付与ごとに 1 行（`grants`）で持ち、購入の付与（1回の購入ごとに同じ量）と無料の付与（新しいアカウントに一度だけ）を分ける。量は「値付けの値」に持つ。
- 呼ぶ前に残りがあるかだけを見て、呼んだ後に引く。最後の 1 回は残りを超えても通す。応答が届かなかった回は引かない。
- 引くときは購入の付与を古い順に使い、無料の付与は最後に使う。
- **使った分の記録**（消費税の申告のため）: 引くたびに、どの付与からいくら引いたかを `consumptions` に 1 行ずつ残す。購入の付与からの分は、売値に直した額（`purchases.amount` × `consumptions.milli_yen` ÷ `grants.granted`。単位は `purchases.currency` の最小単位）を、その購入の MP の有無・カードの発行国・アクセス元の国と結んで集計できるようにする。無料の付与からの分は課税売上にならないので、分けて数える。
- Mawok には残りを割合（%）で見せる。金額や回数には直さない。切り上げで、使い切ったときだけ 0%。
- 無料の付与の止め方: その月に付けた無料の付与の合計が上限に達したら、新しいアカウントに付けるのを止める（付けた分は使える）。付けた分が全部使われても、その月に付けた分の原価は上限に収まる。止めたアカウントには、翌月以降に Mawok が残りを問い合わせるか中継するときに付ける。上限は「値付けの値」に持つ。

## 値付けの値

- 購入と無料の付与の量・無料の付与の月の上限・Gemini の単価・円の換算は、売値と並べると原価の割合が分かるので、リポジトリに書かず秘密の値（`wrangler secret put`）に置く（`src/pricing.ts`）。
- 1つでも無いか読めなければ、窓口のどの入口も DB に書く前に 500 で止める。誤った値で付けたり引いたりせず、サインインのリンクを使ってから止まるような、やり直せない途中で止まらないため。
- `dev.vars.example` の値は、手元とテストのための本番とは違う値。

## 購入

- Stripe の Checkout で売り、Webhook で付与する。日本の外からの買い手には Managed Payments（MP）で売る。購入は台帳（`purchases`）に残す。目印は `mawok-ai`、Price は `STRIPE_AI_CREDITS_PRICE_ID`。
- 料金ページから窓口の最終確認画面へ進む。Mawok の「クレジットを購入」と残高切れの帯は料金ページを開く。付与は Webhook でだけ行う。
- 返金・不審請求の申し立てが届いたら、その購入の付与の残りだけを取り消す（使った分は取り戻さない。MP の返金が使った後に来ても同じ）。

## Pro

- Pro は月額 480 円・年額 4,800 円（税込み）の Stripe Checkout のサブスクで売る。日本からの買い手には直接、それ以外には Managed Payments で売る。Price は秘密の値 `STRIPE_PRO_MONTHLY_PRICE_ID`・`STRIPE_PRO_YEARLY_PRICE_ID` がそろったときだけ売る。
- 料金ページから `GET /account/buy?plan=monthly|yearly` の最終確認を開く。最初の申し込みでは Stripe Checkout に 14 日の試用を渡し、カードを登録する。アカウントの `subscriptions` に一度でも行があれば、試用は渡さない。
- `invoice.paid` で Stripe から請求書とサブスクを取り直し、`subscriptions.paid_through` を請求した期間の終わりまで延ばす。試用の始まりの 0 円の請求書も期限を延ばすが、購入の台帳には残さない。Price・明細・支払い方が受け付けられない Pro の請求書、または Pro の Price が未設定の請求書は、`OPERATOR_EMAIL` があれば運営者へ知らせて webhook を失敗として残し、無ければログに残す。同じアカウントに有効な別のサブスクがある請求書は、台帳を残して Stripe 側で解約し、運営者へ知らせる。返金するかは運営が判断する。Pro は、打ち切られておらず `paid_through` と `cancel_at` の早いほうが今より後なら有効とする。試用かどうかは、そのサブスクに取り消していない Pro の支払いの台帳があるかで決める。`customer.subscription.updated`・`deleted` は状態・`cancel_at_period_end`・`cancel_at` をそれぞれ合わせる。`cancel_at` が `paid_through` 以下なら、更新されずその日時まで使える。返金または不審請求は、Pro の請求ならそのサブスクと、そのアカウントの失効していない Pro の付与の残りを取り消す。
- `GET /v1/balance` は `pro: { active, until, plan, trial }` を返す。`until` は `paid_through` と `cancel_at` の早いほうの UNIX 秒。アプリは通信できないときも、ここで受けた期限の 7 日後まで Pro として扱う。
- 有効で試用中でない Pro には、残高の問い合わせまたは中継のときに、Asia/Tokyo の暦月ごとに 1 回だけクレジットを付ける。値は秘密の値 `PRO_MONTHLY_GRANT_MILLI_YEN`（月額）または `PRO_YEARLY_GRANT_MILLI_YEN`（年額）で、月末に失効する。引く順は失効していない Pro、古い購入、無料の順で、残りの割合には失効した付与を含めない。
- アカウントの画面には、更新される試用なら課金の開始日と解約方法、更新されない試用なら課金されず使える期限、支払い済みなら次の自動更新日または更新されずに使える期限、Stripe のカスタマーポータルを出す。別の購入へ移るとき、古い Checkout Session は Stripe 側で閉じる。閉じられないときも予約を作り直し、古い画面は Stripe の期限で閉じる。削除のスクリプトは、アカウントを消す前に Stripe のサブスクと開いている Checkout Session をその場で閉じる。削除後に開いたままの Checkout が払われたときもサブスクを解約する。サブスク行は持ち主と Stripe の customer id を外して残す。

## 同期

- 有効な Pro（試用中を含む）は、同じアカウントに結んだ Mawok の間で、設定を項目ごとに、テキストウィンドウの履歴を最大 100 件で同期する。アプリはペアリングで受け渡した共通の鍵で中身を暗号化し、窓口は暗号文と鍵の見分けの印だけを置く。窓口が内容を読まず、ログにも残さないため。
- 書く要求は、機器が最後に見た版と照らして全項目を一度に書く。1つでも食い違えば何も書かず、今の暗号文を返す。並行した機器の更新を混ぜず、アプリが取り直してから送り直せるようにするため。
- 消した項目は記録として 90 日置く。古い記録を掃除した後の機器には、窓口の写しで組み直すよう知らせる。鍵を失くして作り直すときも、前の写しを消して同じ組み直しをさせる。
- 1項目は 256 KiB、アカウント全体は 16 MiB、1回は 100 項目までにする。暗号文だけでも、窓口の容量と通信量を際限なく使わないため。
- Pro が終わった写しは 90 日後に消す。サブスクが無いアカウントの写しも消す。
- Mawok は `GET /v1/sync` で受け取り、`PUT /v1/sync` でまとめて書き、鍵を失くしたときだけ `POST /v1/sync/reset` を使う。読む応答の `more` があれば `next` を `since` にして続け、組み直し中は `rebuild=1` も付ける。`more` が終わったときの `next` を次の `since` にする。
- `reset: true` なら、窓口の写しで組み直す。`conflict` は今の項目を取り直して合わせてから書き直し、`key_mismatch` はペアリングし直すか reset を案内する。413 の `limit` は `item`・`total`・`request` のどれが大きすぎたかを表す。

## Mawok の側

- AI サービスの選択肢に「Mawok」がある。キーの代わりにサインインがあれば使える。モデルは選ばせない。
- 了解の画面には、送り先（窓口と Gemini）と扱いを出す。窓口は内容を残さず、Gemini の有料枠の扱い（55 日の保持）に従う。
- 設定の「アクション」に、サインインの状態・残りの割合・「クレジットを購入」・「サインアウト」を出す。残りは、設定の「アクション」を開いたときと、設定のウィンドウに戻ったとき（窓口で買い足して戻るなど）に窓口へ問い合わせる。
- 失敗の種類に「サインインが要る」（トークンが失効した）と「残高が足りない」がある。

## アカウントを消す

- 問い合わせを受けて、運営者がスクリプト（`account-server/scripts/delete-account.mjs`）で消す。
- 付与・トークン・セッション・同期の写しは消す。購入の台帳と使った分の記録は、アカウントとの結び付きを外して 7 年残す（消費税の帳簿の保存期間）。台帳には MP の取引かと国内の取引かを残し、国（カードの発行国・アクセス元の国）は消す。国内の取引かは、買い手の住所の国、無ければカードの発行国、それも無ければアクセス元の国で決める。
- 使われないアカウントは自動では消さない。
