# 同じ LAN の自分のデバイスを追加する

Mawok は、同じ LAN にある自分のデバイスを確認コードで追加し、共有の鍵を渡す。共有の鍵は、Pro の同期（`docs/sync.md`）の暗号に使う。デバイスどうしが直接つなぎ、窓口（account-server）を通らないので、追加にサインインも Pro も要らない。LAN でやり取りするのは、名乗り・確認コードの握手・共有の鍵・生存確認だけで、テキストは渡さない。

TCP はポート 47626、UDP はポート 47625 を使う。ペアリング・生存確認とも、接続の読み書きは10秒で打ち切る。

## 共有の鍵

確認コードでつないだデバイスの組は、32バイトの乱数を1つ共有する。OS の資格情報管理の `mawok-account` の項目に、サインインのトークンとともに `key` の欄へ小文字の16進で置く（サインインしていなければ、項目は鍵だけになる）。設定ファイル、`pro-state.json`、ログには置かない。

同じ鍵から HKDF-SHA256 で用途ごとの32バイトを導く。info は次で固定する。

| 用途 | info | 値 |
| --- | --- | --- |
| 窓口に渡す鍵の見分け | `mawok key id v1` | 小文字の16進64文字の `key_id` |
| LAN の事前共有鍵 | `mawok lan v1` | Noise の事前共有鍵 |

鍵は、確認コードを表示したデバイスが、相手の入力した確認コードが合っていたときに、まだ持っていなければ作る。Pro のデバイスはここでは作らず、窓口と照らして決める（下の「同期との結び付き」）。照らす前に作ると、窓口が覚えている鍵と違う鍵を相手に渡すため。確認コードを入力したデバイスは、受け取った鍵で手元の鍵を置き換える。サインアウトしても、別のアカウントへサインインしても、鍵は消さない。

### 同期との結び付き

Pro の同期（`docs/sync.md`）は、同じ共有の鍵を使う。窓口には鍵そのものではなく `key_id` だけを渡す。Pro が有効になった後、`GET /v1/sync?since=0&limit=1` の `key_id` と手元の鍵を照らし、同期の鍵の状態を決める。

| 状態 | 条件 |
| --- | --- |
| `None` | Pro でないか、サインインしていない。窓口へつながらず手元にも鍵がないときもこの状態。 |
| `Ready` | 手元に鍵があり、窓口の `key_id` と一致する。窓口へつながらず、手元に鍵があるときもこの状態。 |
| `NeedsPairing` | 窓口に `key_id` があるのに手元に鍵がない、または手元の鍵の `key_id` が違う。 |

- 窓口の `key_id` がないときは、手元の鍵を使うか新しく作り、`POST /v1/sync/reset` にその `key_id` を送る。新しく作った鍵は、窓口への送信が成功してから資格情報管理に置く。Pro になる前に追加したデバイスの組は、こうして同じ鍵のまま同期を始める。
- `NeedsPairing` でも、手元の違う鍵は消さない。同期しているデバイスの確認コードを入力すると、受け取った鍵で置き換わる。
- Pro のデバイスが確認コードを入力して共有の鍵を受け取ったときは、窓口と照らし直す。

## デバイスを追加する

片方のデバイスが6桁の確認コードを表示し、もう片方が入力する。画面（設定の「デバイス」）は、次のように出し分ける。

| このデバイス | 出す操作 |
| --- | --- |
| 同期の鍵の状態が `NeedsPairing` | 確認コードの入力と、「このデバイスから始め直す」 |
| 追加したデバイスが無い | 確認コードの表示と、確認コードの入力 |
| 追加したデバイスがある | 確認コードの表示と、「すべてのデバイスの接続を解除」 |

追加したデバイスがあるのに確認コードを入力できるのは、`NeedsPairing` のときだけにする。入力すると鍵が置き換わり、前の鍵でつないだデバイスが一覧から消えるため。ほかの組に入り直すには、先に接続を解除する。`NeedsPairing` のデバイスは、確認コードを表示できない（渡す鍵が窓口の鍵と違うため）。

表示中の確認コードは使える残り時間とともに出し、2分で切れるか相手が1回つないで失敗すると、次のコードに替える。成功したとき、利用者が「キャンセル」を押したとき、確認コードを表示していた設定の「デバイス」を閉じたときは終える。

コードは SPAKE2 で鍵にしてから、`Noise_XXpsk2_25519_ChaChaPoly_BLAKE2s` の握手に使う。握手の後の暗号化された通り道で、次の順に進める。

1. 確認コードを表示したデバイスが、32バイトの共有の鍵を送る（無ければ、ここで作って資格情報管理に置く）。
2. 確認コードを入力したデバイスが Pro なら、窓口の `key_id`（まだ照らせていなければ、手元の鍵の `key_id`）を、受け取った鍵から導いた値と照らす。違えば鍵を置かず `key_mismatch` で終える（同期している鍵を、別の組の鍵で置き換えないため）。
3. 資格情報管理に置いて ACK を返す。手元の鍵が替わったときは、`devices` と見つけ済みの記録を空にする。

成功したら、名前、公開鍵、最後に見たアドレスを設定ファイルの `devices` に置く。名前はコンピューター名で、同じ名前が重なったときは公開鍵の先頭4文字を添えて表示する。

デバイスを1台だけ外す操作は無い。鍵を持つデバイスは全部つながるので、1台を使えなくするには、残すデバイスの全部で「すべてのデバイスの接続を解除」し、追加し直す。解除は次のように動く。

- 同期していない（Pro でない）デバイス: 手元の鍵を消し、`devices` と見つけ済みの記録を空にする。
- Pro のデバイス: 鍵を作り直して `POST /v1/sync/reset` に新しい `key_id` を送り、受け付けられてから置き換える。ほかのデバイスの同期は `NeedsPairing` になり、このデバイスの確認コードを入力するまで止まる。「このデバイスから始め直す」も同じ。

## 相手の確かめ

生存確認は `Noise_IKpsk1_25519_ChaChaPoly_BLAKE2s` を使い、共有の鍵から導いた LAN の事前共有鍵を `psk(1, …)` に入れる。受ける側は最初の握手メッセージで、相手が同じ鍵を持つことを確かめられる。公開鍵をまだ `devices` に覚えていなくても、同じ鍵を持つ相手なら握手は通る。同じ共有の鍵を持つことだけが相手の条件で、アカウントと Pro は確かめない。

つないだ直後の1バイトが、ペアリングでも生存確認でもない接続は、何も返さずに切る。

## 見つけ方

共有の鍵を持つデバイスは UDP で `mawok4 hello <公開鍵>` を3秒おきに名乗る。確認コードを表示している間は `mawok4 pair <公開鍵>` を1秒おきに名乗る。まだ一覧にない公開鍵を受けたら、生存確認を1回試す。成功した相手は握手の payload で受け取ったコンピューター名とともに `devices` に加える。すでに見つけたデバイスは、名乗りと握手で見た新しいアドレスを覚える。生存確認を受けた側も、同じ流れで相手を見つける。自分の公開鍵は無視する。

UDP の名乗りを根拠にした生存確認に失敗した公開鍵は10分間試さない。同じ LAN に別の組の Mawok があっても、名乗るたびに接続を試さないためである。相手からの生存確認の握手が通ったときは、この待ち時間にかかわらず見つける。

同期の鍵の状態が `NeedsPairing` のデバイスが設定の「デバイス」を開いている間は、`mawok4 want <公開鍵> <account_id の SHA-256 の印>` を1秒おきに名乗る。同じアカウントで `Ready` のデバイスは同じ印の要求を2分間覚え、設定の「デバイス」を開いていればコードの表示を自動で始める。閉じている間に見た要求も、2分以内に開いたときに使う。自動で出したコードは、表示中に切れるか相手が試して失敗した後も、同じ要求が続く間は次のコードに替える。

## 待ち受け

TCP と UDP の待ち受けを開くのは、共有の鍵を持つとき、またはペアリングの途中だけにする。途中には、確認コードを表示している間、確認コードを入れて相手を探している間、`NeedsPairing` のデバイスが設定の「デバイス」で `want` を名乗っている間を含む。使わない人に Windows のファイアウォールや macOS のローカルネットワークの許可を求めない。

## 失敗したときの案内

Rust 側は失敗を符号で返し、画面は次の案内を出す。詳しい接続エラーはログにだけ残す。

| 符号 | 案内・扱い |
| --- | --- |
| `lan.unreachable` | 相手の Mawok、同じネットワーク、ファイアウォールまたはローカルネットワークの許可を確かめる。 |
| `lan.needs_pairing` | このデバイスは確認コードを表示できない（同期の鍵の状態が `NeedsPairing`）。設定の「デバイス」を開いて、そこに出る案内を確かめる。 |
| `lan.not_ready` | Pro のデバイスで、窓口と照らした共有の鍵がまだ無いので、確認コードを表示できない。インターネットにつながっているか確かめて、もう一度試す。 |
| `lan.key_mismatch` | 同期しているデバイスで確認コードを表示して、もう一方のデバイスで入力する。 |
| `lan.bad_code` | 確認コードは6桁の数字で入れる。 |
| `lan.wrong_code` | もう一方のデバイスの設定の「デバイス」に今表示されている確認コードを入力し直す。 |
| `lan.internal` | 詳しくはログを確認する。 |
