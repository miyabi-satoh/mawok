# 同じ LAN の自分のデバイスへ送る

Pro の Mawok は、同じアカウントのデバイスへテキストを送れる。送ったテキストは受け取ったデバイスのテキストウィンドウに入り、クリップボードは共有しない。Pro の状態は窓口で確認し、窓口につながらないときだけ、最後に Pro だった期限の7 日後まで使う。

TCP はポート 47626、UDP はポート 47625 を使う。送るテキストは1 MiBまでで、送受信・生存確認とも接続の読み書きは10秒で打ち切る。

## アカウントの鍵

アカウントごとに32バイトの乱数を1つ持つ。OS の資格情報管理に、`mawok-account-key` を user として小文字の16進で置く。設定ファイル、`pro-state.json`、ログには置かない。

同じ鍵から HKDF-SHA256 で用途ごとの32バイトを導く。info は次で固定する。

| 用途 | info | 値 |
| --- | --- | --- |
| 窓口に渡す鍵の見分け | `mawok key id v1` | 小文字の16進64文字の `key_id` |
| LAN の事前共有鍵 | `mawok lan v1` | Noise の事前共有鍵 |

窓口には鍵そのものではなく `key_id` だけを渡す。Pro が有効になった後、`GET /v1/sync?since=0&limit=1` の `key_id` と資格情報管理の鍵を照らす。

| 状態 | 条件 |
| --- | --- |
| `None` | Pro でないか、サインインしていない。窓口へつながらず手元にも鍵がないときもこの状態。 |
| `Ready` | 手元に鍵があり、窓口の `key_id` と一致する。窓口へつながらず、手元に鍵があるときもこの状態。 |
| `NeedsPairing` | 窓口に `key_id` があるのに手元に鍵がない、または手元の鍵の `key_id` が違う。違う鍵は資格情報管理から消す。 |

窓口の `key_id` がないときは、手元の鍵を使うか新しく作り、`POST /v1/sync/reset` にその `key_id` を送る。新しく作った鍵は、窓口への送信が成功してから資格情報管理に置く。鍵を作り直すときも、新しい鍵の `key_id` を `reset` で受け付けられてから置き換える。作り直すと、ほかのデバイスはこのデバイスとペアリングし直すまで送受信と同期ができない。

サインアウトしたとき、または別のアカウントへサインインしたときは、手元のアカウントの鍵を消す。

## デバイスを加える

鍵を持つ `Ready` のデバイスだけが6桁のコードを表示でき、`NeedsPairing` のデバイスだけがコードを入力できる。コードは2分で切れ、相手が1回つなぐと成否にかかわらず使えなくなる。コードを表示していた設定の「デバイス」を閉じたときも切れる。

コードは SPAKE2 で鍵にしてから、`Noise_XXpsk2_25519_ChaChaPoly_BLAKE2s` の握手に使う。握手の後の暗号化された通り道で、次の順に確かめる。

1. 両方が Pro かを確かめ、`account_id` の SHA-256 の印を照らす。違えば `account_mismatch` で終える。
2. コードを表示したデバイスが、32バイトのアカウントの鍵を送る。
3. コードを入力したデバイスは、窓口から知っている `key_id` があれば受け取った鍵から導いた値と照らす。違えば鍵を置かず `key_mismatch` で終える。一致するか、まだ窓口の `key_id` がなければ資格情報管理に置いて ACK を返す。

成功したら、名前、公開鍵、最後に見たアドレス、送信先にするかを設定ファイルの `devices` に置く。名前はコンピューター名で、同じ名前が重なったときは公開鍵の先頭4文字を添えて表示する。

デバイスを1台だけ外す操作は無い。鍵を持つデバイスは全部つながるので、1台を使えなくするには、アカウントの鍵を作り直し（画面の「すべてのデバイスの接続を解除」）、残すデバイスを追加し直す。鍵が替わったとき・消えたとき（作り直し、サインアウト、手元の鍵が窓口の `key_id` と合わなくなったとき）は、`devices` と見つけ済みの記録を空にする。新しい鍵を持つデバイスは、次の名乗りで `devices` に戻る。

## 相手の確かめと送受信

送信と生存確認は `Noise_IKpsk1_25519_ChaChaPoly_BLAKE2s` を使い、アカウントの鍵から導いた LAN の事前共有鍵を `psk(1, …)` に入れる。受ける側は最初の握手メッセージで、相手が同じ鍵を持つことを確かめられる。公開鍵をまだ `devices` に覚えていなくても、同じ鍵を持つ相手なら握手は通る。

送信・生存確認では、握手の後に `account_id` の印を送り直して照らさない。同じアカウントの鍵を持つことが相手の条件である。送る側は Pro で `Ready` でなければ送らず、受ける側が Pro でなければ `pro_required` を返す。

テキストウィンドウの「送信」と送るキーは、`devices` にデバイスがあるときだけ使える。送信先にチェックしたデバイスへ同時に送り、最後に名乗りで見たアドレス、なければ設定に覚えたアドレスへつなぐ。送信先を選ぶ一覧を開くときは各デバイスへ1回生存確認し、握手と Pro の確認を通ったデバイスだけをチェックできる。

受け取ったテキストは前面には出さない。入力欄が空ならそのまま入れ、書きかけがあれば「カーソルの位置に挿入」か「破棄」を選ばせる。テキストは履歴・ディスク・ログには残さない。

## 見つけ方

`Ready` のデバイスは UDP で `mawok3 hello <公開鍵>` を3秒おきに名乗る。コードを表示している間は `mawok3 pair <公開鍵>` を1秒おきに名乗る。まだ一覧にない公開鍵を受けたら、生存確認を1回試す。成功した相手は握手の payload で受け取ったコンピューター名とともに `devices` に加え、送信先へチェックを入れる。すでに見つけたデバイスは、名乗りと握手で見た新しいアドレスを使う。生存確認や下書きを受けた側も、同じ流れで相手を見つける。自分の公開鍵は無視する。

UDP の名乗りを根拠にした生存確認に失敗した公開鍵は10分間試さない。同じ LAN に別アカウントの Mawok があっても、名乗るたびに接続を試さないためである。送信または生存確認の握手が通った相手は、この待ち時間にかかわらず見つける。

`NeedsPairing` のデバイスが設定の「デバイス」を開いている間は、`mawok3 want <公開鍵> <account_id の SHA-256 の印>` を1秒おきに名乗る。`Ready` のデバイスは同じ印の要求を2分間覚え、設定の「デバイス」を開いていればコードの表示を自動で始める。閉じている間に見た要求も、2分以内に開いたときに使う。自動で出したコードが使われるか切れた後も、同じ要求が続いていれば次のコードを出す。

## 待ち受け

TCP と UDP の待ち受けを開くのは、Pro で鍵が `Ready` のとき、またはペアリングの途中だけにする。途中には、コードを表示している間、コードを入れて相手を探している間、`NeedsPairing` のデバイスが設定の「デバイス」で `want` を名乗っている間を含む。使わない人に Windows のファイアウォールや macOS のローカルネットワークの許可を求めない。

## 失敗したときの案内

Rust 側は失敗を符号で返し、画面は次の案内を出す。詳しい接続エラーはログにだけ残す。

| 符号 | 案内・扱い |
| --- | --- |
| `lan.no_device` | 設定の「デバイス」でほかのデバイスを追加するか、追加済みのデバイスを同じネットワークにつなぐ。 |
| `lan.no_target` | 「送信」の横の送信先一覧でデバイスを選ぶ。 |
| `lan.unreachable` | 相手の Mawok、同じネットワーク、ファイアウォールまたはローカルネットワークの許可を確かめる。 |
| `lan.refused` | 相手の Mawok が動いているか確かめる。 |
| `lan.pro_required` | このデバイスで Pro を使えるアカウントにサインインする。 |
| `lan.needs_pairing` | 設定の「デバイス」を開いて、そこに出る案内（コードの入力、または準備ができなかった旨）を確かめる。 |
| `lan.receiver_pro_required` | 送り先のデバイスで Pro を使えるアカウントにサインインする。 |
| `lan.account_mismatch` | コードを入れるデバイスが別のアカウントなら、同じアカウントでサインインする。 |
| `lan.key_mismatch` | 新しい鍵を持つ別のデバイスのコードを入力する。どのデバイスにも無いときは、鍵を作り直す。 |
| `lan.too_long` | テキストを1 MiB以下にする。 |
| `lan.bad_code` | コードは6桁の数字で入れる。 |
| `lan.wrong_code` | 相手でコードを表示し直す。 |
| `lan.partial` | 一部のデバイスにだけ届かなかった。書いたテキストは残す。 |
| `lan.internal` | 詳しくはログを確認する。 |
