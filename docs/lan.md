# 同じ LAN の自分の機器へ送る

- 同じネットワークにある別の機器の Mawok とペアリングしておき、テキストをその機器のテキストウィンドウへ送る。Mac と Windows を並べて使うときに、片方で書いたテキストをもう片方で貼れるようにする。
- クリップボードそのものを共有する形は採らない。OS の機能（ユニバーサルクリップボードなど）と重なり、「クリップボードの履歴に残さない」でコピーを広げない作りと逆向きになるため。テキストとして送れば、受け取った側が中身を確かめてからコピーする。
- 次のものは作らない。
  - ファイアウォールが受信を止めていることの判定。通信の失敗は原因を判定しない（下の「失敗したときの案内」）。
  - 相手が見つからないときに、アドレスを手で入れる道。効くのはブロードキャストを止めるルーターだけで、端末どうしの通信そのものを止める Wi-Fi ではアドレスを入れてもつながらないため。
  - コードを表示した側が、違うコードで使われたと知る表示。ペアリングは同じ人が両方の画面を見ていて、コードを入れた側に「コードが違うか、もう使えない」が出るため。
- ペアリング:
  - 設定の「機器」で、片方の機器が 6 桁のコードを表示し、もう片方の機器でそのコードを入力する。
  - コードは2分で使えなくなる。画面には「あと N 秒」と残り秒を出す。1回つながったら、コードが違っていても使えなくなる（違うコードで何度も試させない）。コードを表示した設定ウィンドウを閉じても使えなくなる。使えなくなったら、画面に出していたコードも消す（出し続けると、入れ直した相手が見つからずに失敗するため）。
  - ペアリングすると、互いの公開鍵と名前（コンピューター名）を覚える。macOS は `hostname` のローカルホスト名ではなく、`scutil --get ComputerName` のコンピューター名を使う（ローカルホスト名は、同じ名前の機器が LAN にいると見なされると macOS が番号を付け替えるため）。設定ファイルの `paired_devices` に、名前・公開鍵・最後のアドレスを持つ。
  - この機器の鍵は、設定ファイルと同じフォルダーの `device-key` に置く。設定ファイルは人に見せることがあるので分ける。初めてペアリングするときに作る。
  - 何台でもペアリングできる（上限は設けない。自分の機器だけなので、上限で守るものがない）。同じ機器とペアリングし直すと、前の分を置き換える。設定の「機器」の「解除」で、その機器だけを忘れる。ペアリングの操作は、ペアリングした機器の一覧の下にいつも出す。
  - 新しくペアリングした機器は、送信先にチェックを入れた状態で加える（ペアリングしたのは送るため）。送信先を選べるようになる前の設定ファイルで `send_to` がない機器も、チェックを入れて読む。
  - 仕組み: コードから SPAKE2 で鍵を作り、それを事前共有鍵にした Noise（`Noise_XXpsk2_25519_ChaChaPoly_BLAKE2s`）で公開鍵を交換する。コードをそのまま鍵にしないのは、やり取りを盗み見た相手に総当たりで当てられるため。
- 見つけ方: UDP のブロードキャスト（ポート 47625）で、3秒おきに公開鍵を名乗る。コードを表示している間は1秒おき。
  - mDNS は使わない。無線の端末どうしのマルチキャストを中継しないアクセスポイントがあるため。Wi-Fi で試したとき、mDNS は見つからず、ブロードキャストは届いた。
- 待ち受け: ペアリングした機器があるか、ペアリングの途中のときだけ、TCP（ポート 47626）と UDP を開く。使わない人には OS の許可（Windows のファイアウォール、macOS のローカルネットワーク）を求めない。
- 送る:
  - テキストウィンドウで送るキー（既定は Cmd+Shift+Enter、Windows は Ctrl+Shift+Enter）を押すか、下の列の「送信」を押すと、送信先にチェックした機器へ送る。ペアリングした機器がなければ、キーは効かず、ボタンも出さない。IME の変換中は、コピーのキーと同じく効かない。
  - 送信先にチェックした機器が1台もなければ、送らずに送信先の一覧を開く。
  - 送信先の一覧:
    - 「送信」の横の▼で開く。ペアリングした機器を並べ、チェックを入れた機器へ送る（一斉に送るのを基本に、選べるようにする）。
    - チェックは設定ファイル（`paired_devices` の `send_to`）に覚え、次に開いたときや、一覧を開かずにキーで送るときにも使う。
    - 開いたときに、各機器へ一度だけ生存確認をする（Mawok の待ち受けへつなぎ、握手まで行って切る。ペアリングした本人かも確かめる）。確かめている間は「つながるか確かめています」と出す。周期的には確かめない（使っていない間も通信し続けると、ノートのバッテリーやスリープの妨げになるため）。OS の ping（ICMP）は、Windows のファイアウォールが既定で止めているので使わない。
    - 生存確認でつながらなかった機器は、チェックできず「つながりません」と出す。チェックを覚えていても外れて見せ、一覧から送るときも送らない。相手を起動したあとは、一覧を開き直せば確かめ直す。
    - 同じ名前の機器が2台以上あるときは、名前の後ろに公開鍵の先頭4文字を半角のかっこで添えて見分ける（例: `mac-mini (de03)`。名前はコンピューター名なので、重なることがある）。設定の「機器」の一覧でも同じ見分け方にし、どれを解除するか分かるようにする。
    - キーボードでは、↑↓ で移り、Space でチェックを入れ外しし、Enter でチェックした機器（つながったものだけ）へ送り、Esc で閉じる。
  - 送るのは、整える前の入力欄の中身。置き換え辞書などは、受け取った側がコピーするときに、受け取った側の設定で当てる（整えるのはクリップボードへ渡すときだけ、と揃える）。
  - 送っている間（つないで送り終えるまで、数秒かかることがある）は、入力欄を書き換えられず、「送信」は「送信中…」になって押せない。アクション一覧を開くキーとボタンも効かない（アクションは入力欄を書き換えるため）。
  - 送信先の全部に送れたら、コピーして閉じるときと同じく、閉じて入力欄を空にし、履歴に覚える。送った側のクリップボードは変えない。入力欄が空なら、何も送らずに隠す。
  - 一部の機器にだけ届かなかったら、隠さずに「一部の機器に届きませんでした」と、届かなかった機器の名前を帯で出し、書きかけを残す。原因は出さない。送り直すと、届いた機器にもう一度届く（気になるなら、チェックを外してから送り直す）。
  - 送っている間にほかのアプリへ移っていたら、送れても隠さず、フォーカスも戻さない。戻り先へフォーカスを戻すと、移った先から奪ってしまうため。
  - 1台にも送れなかったら、隠さずに帯でその旨を出し、書きかけを残す。帯には、失敗の種類ごとに何をすればよいかの案内を出す（下の「失敗したときの案内」。台数が多ければ、最初の機器の種類）。
  - 仕組み: Noise（`Noise_IK_25519_ChaChaPoly_BLAKE2s`）でつなぎ、ペアリングした公開鍵の相手とだけ送り合う。送信先は、名乗りで最後に見たアドレス。まだ見ていなければ、設定ファイルに覚えたアドレス。1回に送れるのは 1 MB まで。機器ごとに同時に送り、動いていない機器を待つ時間が台数分重ならないようにする。
- 受け取る:
  - 前面には出さない。入力欄が空なら、そのまま入力欄に入れる。
  - テキストウィンドウが隠れている間に届いたら、トレイのアイコンの右上に点を付け、ツールチップに「届いたテキストがあります」と添える。テキストウィンドウを出したら（ホットキー、トレイの「テキストウィンドウを表示／隠す」、設定を閉じたときの出し直しのどれでも）消す。出ている間に届いたときは、入力欄か帯で見えるので付けない。アクションを実行している間に届いた分も、届いたときにテキストウィンドウが出ているか隠れているかで同じように決める（出ていれば付けず、実行が終わってから帯で知らせる）。起動し直すと消える（届いたテキストも起動中だけ持つため）。
  - 書きかけがあれば溜めておき、テキストウィンドウに帯で知らせ、「カーソルの位置に挿入」か「破棄」かを選ばせる。2件以上届いたら、届いた順に1件ずつ知らせる。
  - 挿入は、定型文と同じく入力欄の取り消しで戻せる。
  - 受け取ったテキストは履歴へは入れず、ディスクに書かない。ログにも中身は残さない。画面の読み込み中（起動した直後や、描画プロセスが落ちて読み込み直している最中）に届いた分は、Rust 側で起動中だけ溜めておき、読み込みが終わったら画面へ渡す。相手には受け取れたと返しているので、ここで失わないため。
  - 受け取っている間にペアリングを解除したら、受け取り終えても入力欄に入れず、相手にも受け取れたと返さない。ペアリングした相手かは、つないだときと、受け取り終えて画面へ渡すときの2回、そのときの設定で確かめる。2回目は、解除と食い違わないよう設定を押さえたまま確かめて溜め、溜められたときだけ相手に受け取れたと返す。
  - 続けて届いても、届いた順に入れる。画面が溜まった分を取りに行くのは一度に1回だけにし、取りに行っている間に届いた分は、終わってからもう一度取りに行く。
  - 画面が溜まった分を取り出した直後、入力欄に入れる前に描画プロセスが落ちたときは、そのテキストは失われる。入力欄に入れた後に落ちたときも、入力途中の内容と一緒に失われるので、取り出しの後まで守る仕組みは持たない。

- 失敗したときの案内:
  - Rust 側は失敗を種類に分けて符号で返し、画面は符号から、何をすればよいかの案内を出す。詳しい中身（接続のエラーなど）は、調べるときのためにログにだけ残す。
  - 分けるのは、原因がはっきり分かり、原因によって利用者の行動が変わるときだけ。自分たちのロジックで判断した失敗は分けて出す。ネットワークや OS、ファイルから返ったエラーは原因を追いかけず、まとめて出す（推測で原因を言うと、外れたときに迷わせるため）。
  - 帯はテキストウィンドウ（既定で小さい）にも出るので、案内は1〜2文に収める。
  - 分けて出すもの:
    - ペアリングした機器がない: 設定の「機器」でペアリングする。
    - つながったが受け取らなかった（相手でペアリングを解除した、相手の鍵が作り直された、途中で切れたなど）: 相手でペアリングが解除されていたら、両方で解除してペアリングし直す。相手の鍵が作り直されたときは、相手を見てもペアリングしたままに見えるので、ペアリングし直しを案内する。
    - テキストが長すぎる: 1 MB まで。
    - コードが6桁の数字でない: 6桁で入れる。
    - コードが違うか、もう使えない: 相手でコードを表示し直す。
  - 「相手とつながらない」にまとめるもの（ペアリングした機器の場所が分からない、相手へつなげない、コードを表示している相手が見つからない）: 相手の Mawok が動いていて同じネットワークにあるか、両方の機器のファイアウォールやローカルネットワークの許可。原因を判定するのではなく、よくある原因を確かめる所として添える。送る側の Mac に許可がないと名乗りを受け取れないので、相手の機器だけに絞らない。
  - 「エラーが起きました」にまとめるもの（待ち受けを始められない、鍵が読めないなど）: 詳しくはログにあることだけを伝える。待ち受けを始められないときは、コードも出さない。
  - コードを入れてから、コードを表示している相手を30秒まで探す。初めて待ち受けるときに出る OS の許可のダイアログを押す間に、切れないようにするため。
