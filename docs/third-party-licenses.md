# 第三者のソフトウェア

- 配布物に含まれる第三者のソフトウェア（依存のパッケージ）と、そのライセンスの本文を出す。設定の「このアプリについて」の「ライセンスを表示」で開く、設定とは別のウィンドウ。呼び名は、利用規約に揃えて「第三者のソフトウェア」にする。
  - 利用規約の第6条（第三者のソフトウェア）が、この画面の名前を書いている。規約の文章は `site/src/content/terms.md`。名前を変えるときは、同じ PR で規約の文章も直す。
- 中身は「アプリ本体」（Rust の依存）と「画面」（画面に同梱した npm のパッケージ）の2つに分ける。それぞれ、**1パッケージ1行**で名前の順に並べ、行には名前・版・ライセンスの式（例: `MIT OR Apache-2.0`）を出す。同じ名前の違う版は1行にまとめ、版を並べる。
  - 幅が足りないときは、名前をハイフンか下線の後ろで折る（下線ではブラウザーが折らないので、`windows_x86_64_msvc` のような名前がライセンスの式を枠の外へ押し出す）。単語の途中では折らない。最小の幅（480）は、どの名前も3行以上に分かれない幅として決めた。
  - 条文は元の改行を保って出す。区切り線（`=` が72個続く行など）のように、空白の無い長い連なりが幅に収まらないときだけ、その途中で折る（折らないと、一覧ごと横にスクロールする）。
  - 形は、規模の近い常駐アプリの Tailscale（「Acknowledgements…」で開く一覧。1パッケージ1行で、名前とライセンス名だけを並べる）に揃えた。条文ごとにまとめて同じパッケージが何度も出る形や、束ごとに数百のパッケージが並ぶ形は、見た人に何の一覧か分かりにくいので採らない。
  - 行を開くと、ソースの置き場所と、そのパッケージの条文を見出し付きで全部出す（著作権表示を含む）。`OR` の式では、Rust は cargo-about が選んだ条文だけを、npm はパッケージが同梱している条文を全部（ファイル名を挟んで）出す。Tailscale はリンク先の LICENSE に任せているが、ライセンス表示はアプリの中に置く決まりなので（ネットを見られない環境でも満たせるように）、条文はアプリの中に持つ。
  - ソースの置き場所（公開元に書かれたリポジトリの URL）はリンクにし、既定のブラウザーで開く。MPL-2.0 の依存が入っており、受け取る人にソースの入手先を知らせる必要があるため。ウィンドウの中では開かない（アプリの画面が置き換わって戻れなくなる）。開くのは https の URL だけ。リンクは開閉の行の中ではなく、開いた中に置く（行の中に置くと、押したときに開閉とリンクのどちらが働くかが紛らわしく、支援技術にも扱いにくい）。
  - 一覧を読めなかったほうは「一覧を読み込めませんでした。」と出し、もう片方は出す。
- 一覧は、ビルドの前後に作る静的なファイルで、配布物に入れる。抽出した結果は元データとして扱い、そのままは見せない。Rust と npm で共通の `scripts/license-display.mjs` が、画面に出す形に整える（1パッケージ1件にまとめる、同じ条文をデータの中で1つにする）。整えるときに、本文の無いパッケージ、著作権者が空欄のひな形、ソースコードの混ざった本文が残っていたら、書き出さずに止める。
  - Rust の分は cargo-about で `just licenses` が作り、`static/third-party-licenses/rust.json` としてリポジトリに入れる。数えるのは、配る2つのターゲット（macOS の Apple シリコンと Windows）で実際にリンクされるクレートだけ（`cargo tree` で、通常の依存を proc-macro を除いて辿る）。cargo-about はビルドのときにだけ動く proc-macro とその依存も数えるが、それらは配らないので出さない。リンクされるのに cargo-about の一覧に無いものがあれば、止める。依存を変えたら作り直してコミットする。`just ci` の `licenses-check` が、作り直して差分が出ないことを確かめる。
    - 条文のファイルを同梱していないクレートや、同梱していても cargo-about が読み取れないクレートは、cargo-about が SPDX のひな形（著作権者が空欄）で埋める。これでは著作権表示が配られないので、ひな形が残っていたら生成を止める。止まったら上流の条文を確かめて、同梱のファイルがあれば `about.toml` の `clarify` で指し、無ければ公開時のコミットの条文を `src-tauri/license-texts/` に置いて差し替える（`scripts/generate-rust-licenses.mjs` の `OVERRIDES`）。取りに行く形（`clarify` の `git`）は、生成がネットを見ることになるので使わない。
    - objc2 系のクレートは、上流が MIT で提供すると書くだけで著作権表示をどこにも掲げていない。上流の文書と MIT の条文をそのまま出し、著作権者の行は書き足さない。winnow・zmij のように、上流の条文がもともと著作権表示の行を持たないものも、そのまま出す。
    - ring は、ライセンスの注釈を頭に持つソースファイルを、cargo-about が丸ごと本文として拾う（コードまで出る）。クレートの LICENSE の案内に従って、ISC（新しいコード。ソースの頭にある ISC の著作権表示も並べる）、Apache-2.0（BoringSSL から取った部分）、MIT（once_cell から取った部分）の条文に差し替える。
  - 画面の分は Vite のプラグイン（`scripts/third-party-licenses.ts`）が、ビルドのたびに `build/third-party-licenses/npm.json` に書き出す。`package.json` の依存ではなく、実際に配る JavaScript に入ったモジュールから集める（lint やテストの道具を混ぜないため）。開発サーバーには無いので、`pnpm tauri dev` では「画面」が読み込めない表示になる。
    - ビルドの道具がバンドルに差し込むコード（Vite の preload-helper と Rolldown の runtime）も、配る物に入るので数える。知らない差し込みが入ったら、ビルドを止める。
    - Vite の条文は、Vite 本体の分だけを出す（Vite が自分の配布物に同梱する依存の条文は、配る物に入らないので出さない）。
    - package.json に置き場所を書いていないパッケージ（svelte-toolbelt）は、上流のリポジトリを確かめて手で補う（プラグインの `REPOSITORIES`）。
  - どちらも、配ってよいライセンスの一覧（`src-tauri/about.toml` の `accepted` と、プラグインの `ACCEPTED`）に無いものが入ると、作るのを止める。中身を確かめてから一覧に足す。
- ウィンドウは OS 標準のタイトルバー付き。常に最前面にはしない。大きさは既定が 640×560、最小が 480×320 で、移動とリサイズができ、最小化と最大化はできない。前回の位置と大きさを記憶する（設定ウィンドウと同じ）。記憶がなければ画面の中央に出す。
  - 設定ウィンドウと同じく、隠した状態で作り、画面を描いたら表示する。すでに開いていれば前面に出す。
  - Esc か Cmd+W（Windows は Ctrl+W）で閉じる（設定ウィンドウと同じ）。
  - **設定ウィンドウを閉じたら、一緒に閉じる。** 設定から開くものなので。残すと、設定を閉じたときに出し直したテキストウィンドウと重なり、macOS では Dock から消えてメニューバーだけの常駐に戻った後も、このウィンドウだけが残る。
